# Long方格正式方格卡片操作区自适应布局审计

## 1. 问题与设计目标

Stage 91、94、95 依次加入“查看并管理”“折叠/展开”“锁定”后，三个文字按钮处于同一水平 StackPanel。该结构在宽窗口可用，但宽度分配没有上限保护；在 720px 紧凑窗口、系统文本放大或中文文案变化时存在挤压、截断和触控目标过密风险。

竞品的对象就近操作优势应保留，但操作数量增加后必须建立清晰层级，而不是继续横向堆叠。

## 2. 交互层级

Stage 96 将卡片操作区改为内在自适应的两行两列 Grid：

- “查看并管理此方格”属于完整上下文入口，独占第一行两列；
- “折叠/展开”和“锁定/已锁定”属于有限快捷动作，在第二行各占一个等宽星号列；
- 行列间距固定使用 8 DIP，三个按钮均横向拉伸到可用单元格；
- 源码与键盘遍历顺序固定为管理、折叠、锁定；禁用动作仍由现有锁状态决定。

该布局不依赖 XAML `AdaptiveTrigger`。项目早期真实 UIA 已证明 AdaptiveTrigger 在窗口缩到 720px 时不够可靠，因此这里使用内容本身即可分配宽度的 Grid，不增加第二套尺寸状态机。

## 3. 无障碍与视觉边界

- 继续使用标准 Button，保留默认键盘、焦点可视化、Invoke 和系统主题行为；
- 不新增或复制 AutomationId，权威 UI 合同保持 137-ID；
- 不使用仅颜色表达主次，按钮文字和状态化可访问名称保持不变；
- 两个快捷动作等宽，避免锁定状态文案变化导致相邻按钮位置跳变；
- 当前自动门禁只证明结构、源码顺序和编译有效，不能替代 200% 文本缩放、Narrator、高对比、触控和 720px 真实窗口人工检查。

## 4. 权限与数据影响

本切片只调整 XAML 布局与结构合同：

- 不改变快速折叠、快速锁定或管理导航策略；
- 不提交配置、不刷新 Catalog；
- 不读取或修改桌面文件；
- 不连接 DesktopHost、任务栏或系统设置；
- 不改变配置 schema、保存、撤销或插件协议。

## 5. 验证结果

- UI 合同通过：2 个 Auto 行、2 个等宽星号列、8 DIP 间距、管理入口跨两列、快捷动作位于第二行且横向拉伸；
- UI 合同验证三个按钮的源码/Tab 顺序，并保持 137 个唯一 AutomationId；
- Release XAML 与完整解决方案构建为 0 warning / 0 error；586 项全量测试通过；
- 覆盖率为 line 91.39%、branch 80.99%，高于 90% / 75% 门槛；
- format、diff whitespace、启动链、干净会话、单实例、VSTest 挂起诊断和依赖漏洞门禁通过；PR/main CI 仍需在发布阶段独立复核，真实无障碍矩阵继续保持 Pending。

结论：该切片以稳定的内在布局替代横向堆叠，在不扩大产品权限和状态复杂度的前提下，为紧凑宽度与文本放大预留了可靠空间。
