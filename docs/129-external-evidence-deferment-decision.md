# Stage 129：外部证据延期与工程主线恢复决策

- 日期：2026-08-13
- 决策基线：`main@e80a521`（PR #178；main CI 31715218811 通过）
- 决策人：ProjectOwner
- 状态：**Approved engineering-sequence change / External evidence remains Pending**

## 1. 决策原因

Stage 125 原顺序要求先完成 C1 五人可用性测试，再执行 C2/C3/C4 人工、硬件和会话矩阵。当前负责人明确确认无法安排真实参与者，因此继续把 C1 作为工程开发入口会让项目无限停留在“会话已就绪、无结果”的状态。

2026-08-13 曾在 `main@e80a521` 启动 P1 匿名会话，但没有参与者进入、没有执行任务、没有记录结果或证据文件；进程已退出且无残留。该启动不计为 P1，不得记录为 Pass、Fail 或 Inconclusive。

## 2. 批准的变更

从本决策合入起采用两条相互约束的轨道。

### 工程轨道

允许继续完成正式产品链，但每个切片仍必须默认关闭、可回滚、无桌面文件写入，并独立审计/推送：

1. **E1 / M1**：正式 Explicit 表面适配器；
2. **E2 / M2**：正式输入源、Intent 消费和可访问交互；
3. **E3 / M3**：配置优先的桌面直接交互 MVP；
4. **E4 / M4-ready**：完成自动化、性能和人工验证入口，使产品达到“等待外部验证”状态；
5. **R1**：仅在 E4 基线稳定后进行等价维护性重构。

### 外部证据轨道

以下门禁全部保持 Pending，Issue 保持 OPEN：

- X1 / C1：Issue #23 P1～P5 五人可用性测试；
- X2 / C2+C3：Issue #19、B6C3、A5、BSA 的物理输入、Narrator、系统表面和正式 Passive 产品矩阵；
- X3 / C4：Issue #20 I20-01～08 动态显示/会话矩阵；
- X4 / C5b：Issue #24 I24-01/I24-02 专用卷真实失败与恢复；
- X5 / C6：基于上述证据完成 ADR-0001 和 Phase 0 退出裁决。

## 3. 不变的硬门槛

本决策只解除“外部排期阻塞工程编码”，不接受风险、不关闭缺陷，也不降低以下门槛：

- E1～E4 的自动化或开发者自测不能替代 X1～X4；
- M4 只能达到 `ReadyForExternalValidation`，不能在 X1～X4 未完成时写 Pass；
- X1～X5 未全部关闭前，不得创建内部 RC 标签、把功能默认开放、签名/安装或公开/内部人群分发；
- Issue #19、#20、#23、#24 保持 OPEN；ADR-0001 保持 Proposed；
- `PendingManualEvidence`、`ResultsPending`、`PendingDedicatedEnvironmentEvidence` 状态保持不变；
- 无许可证、签名和安装生命周期证据时，现有 unsigned 制品继续只作 CI 审计产物；
- 真实文件移动、自动整理、任务栏、Widget 和插件仍不进入本轮。

## 4. 工程切片准入规则

每个 E1～E4 PR 必须：

1. 写明它解决的正式产品链缺口及非目标；
2. 默认 feature flag 关闭，紧急禁用保持最高优先级；
3. Passive/只读状态不得产生 Explicit、Intent 消费或文件写入；
4. 自动化覆盖成功、拒绝、乱序/重复、取消、部分失败、补偿、关闭和资源释放；
5. 保留对应人工入口及 Pending 状态；
6. 更新 Stage 125/129 和专项审计；
7. 经 PR CI、合并和 main CI 后才进入下一切片。

任何工程发现若会改变支持范围、权限、文件行为或外部测试任务，必须停止并先追加负责人决策。

## 5. RC 前证据汇合门

E4 完成后必须停止新功能开发，执行 X1 → X2 → X3 → X4 → X5：

1. 招募五位未参与设计的参与者，完整执行同一 commit 的 P1～P5；
2. 在专用 Windows 11 x64 环境执行输入、Narrator、系统表面和正式产品矩阵；
3. 执行真实显示器、投影、睡眠/RDP 等动态矩阵；
4. 在专用 VM/VHD 执行真实容量/只读卷三阶段；
5. 修复阻断问题后，所有受影响样本和矩阵从新 commit 重新执行；
6. 更新 ADR、关闭或重新分期四个 Issue，并完成 Phase 0/MVP 验证审计；
7. 只有全部通过或有负责人逐项书面 Accepted Risk，才允许进入内部 RC 候选。
