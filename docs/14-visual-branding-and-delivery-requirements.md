# Long方格视觉品牌、动效与交付要求

日期：2026-08-03

状态：**Product Requirement / 尚未实现**

适用范围：正式 `LongGrid.App`、`LongGrid.DesktopHost`、安装包、开始菜单/桌面快捷方式、商店素材和开发脚本

## 1. 当前事实

当前仓库已经建立开发期只读 UI Shell，但仍没有可发布产品 UI：

- 已有 `LongGrid.App`、WinUI/XAML 导航骨架和 Design Token，但只显示匿名示例数据，不枚举真实桌面、不连接 DesktopHost，也不是可发布设置中心；
- 没有正式 `LongGrid.DesktopHost` 产品工程；
- P0-04/P0-05b1 只有 GDI 系统色的交互探针，用于验证 HWND、输入、焦点和 UI Automation，不代表最终视觉；
- 已有经像素校正的 RC1 SVG/PNG 品牌资产，并能在 MSIX 暂存区生成 44/150/50 px 精确图标；最终商标、ICO/商店素材和 Windows 外壳实机矩阵仍未完成；
- 已有 `eng/Start-LongGrid.ps1` 开发启动入口、`eng/Pack-LongGrid.ps1` self-contained 便携 ZIP 和 `eng/Pack-LongGridMsix.ps1` 未签名 MSIX 验证入口；受保护签名和正式安装入口仍不存在。

因此开发期 UI Shell、任何探针窗口、命令行入口或 `dotnet run` 命令都不得宣传为 Long方格正式 MVP 或安装体验。

## 2. 产品名称与标识

- 面向用户的中文产品名：**Long方格**；
- 英文品牌名：**Long Grid**；
- 代码命名空间、程序集前缀和仓库名继续使用 `LongGrid` / `Long_Grid`，避免无收益的大规模重命名；
- 设置页、安装包、开始菜单、窗口标题、关于页和商店素材统一显示“Long方格”；需要双语时使用“Long方格 · Long Grid”；
- 不使用竞品名称、图形结构、配色、截图或资产作为品牌素材。

## 3. 视觉方向

Long方格的正式 UI 必须同时满足：**现代化、扁平化、精致华丽、简约、融入 Windows**。

“华丽”指有品质的层次、材质、色彩和动效，不指堆叠高光、厚重拟物、持续粒子或高资源特效。核心视觉原则：

1. **扁平骨架**：清晰网格、低噪声表面、简洁图标和直接的信息层级；
2. **克制层次**：使用间距、圆角、色阶、轻量阴影和有限材质区分层级；
3. **精致焦点**：渐变、辉光或强调色仅用于主操作、品牌时刻和关键状态，不铺满所有表面；
4. **桌面融合**：容器默认安静，不与壁纸和系统窗口争夺注意力；编辑模式才提高结构对比；
5. **系统适配**：浅色、深色、系统强调色、高对比度、文本缩放和减少动画均为首发基础能力；
6. **性能优先**：空闲状态不得存在持续装饰动画；材质不可用或性能不足时自动降级为纯色表面。

建议以 WinUI 3 + Windows App SDK Stable 构建设置/引导窗口，以 Composition/DirectComposition 实现经过性能验证的桌面宿主视觉。视觉规范不改变 ADR-0001 的 Go/No-Go 门禁。

## 4. 设计系统要求

正式 UI 开发前必须建立可复用 Token，而不是在页面中散落硬编码值：

- 色彩：品牌主色、强调色、中性色、语义色和浅色/深色/高对比映射；
- 字体：遵循 Windows 系统字体与文本缩放，不以图片替代正文；
- 间距：采用一致的 4 px 基础网格；
- 圆角：按控件、卡片、容器和浮层分级，不对所有元素使用同一大圆角；
- 深度：边框、阴影和材质承担不同层级语义；
- 图标：使用统一线宽、端点、视觉尺寸和填充规则；
- 状态：Normal、Hover、Pressed、Selected、Focused、Disabled、Loading、Error、Recovery；
- 响应式：100%–300% DPI、文本缩放、多显示器和窄窗口下不裁切关键操作。

选择态和键盘焦点必须可区分，颜色不能成为唯一状态表达。正式组件至少覆盖 Button、Toggle、Navigation、Card、Container、DesktopItem、Toast、Dialog、Empty/Error/Recovery State。

## 5. 动效合同

动效服务于空间关系、状态变化和操作确认，不用于拖慢操作：

| 类型 | 建议时长 | 要求 |
|---|---:|---|
| Hover/Pressed/Toggle | 80–140 ms | 即时响应，不延迟输入 |
| 小型状态切换 | 120–200 ms | 可中断、可反向 |
| 面板/容器进入退出 | 180–280 ms | 保持来源与目标关系 |
| 布局重排 | ≤ 240 ms | 项目数量大时允许降级或关闭 |

验收要求：

- 以 60 Hz 显示器为基础目标，常规帧预算约 16.7 ms；
- 拖动、缩放和滚动直接跟随输入，不对指针路径做滞后平滑；
- 连续触发时合并动画，不排队播放过时状态；
- 窗口隐藏、全屏避让、显示器恢复和错误回滚不等待装饰动画；
- 开启“减少动画”后取消位移、缩放、视差和非必要模糊，只保留必要淡入淡出或即时切换；
- 高负载、节能、远程会话或不支持材质时自动降级；
- 动效失败不得改变文件、布局或输入门的最终状态。

## 6. “L + 方格”应用图标合同

核心概念：将字母 **L** 与桌面方格/网格融为一个单一几何符号。

推荐构图：

- 使用 3×3 方格作为基础比例；
- 左侧竖列与底部横列共同形成清晰的 L 轮廓；
- 其余少量方格作为“可整理的桌面单元”，通过留白或第二色与 L 区分；
- L 与格子必须共享同一几何系统，不能是字母叠在九宫格上；
- 图形保持正视、扁平、简约，禁止 3D 透视、复杂纹理、细碎高光和小尺寸不可辨文字；
- 主 Glyph 优先使用单色或双色；大尺寸品牌场景可使用非常克制的冷色渐变，小尺寸图标必须回到高对比纯色；
- 不直接复用 Windows、iTop、Fences 或其他品牌的方格排列和颜色。

必须交付：

- 可编辑矢量母版 SVG；
- 单色、双色、浅色背景、深色背景和高对比版本；
- 16、20、24、32、48、64、128、256 px 像素校正版；
- Windows `.ico` 与 MSIX 所需 PNG/StoreLogo/SquareLogo/SplashScreen 资产；
- 安全区、最小尺寸、背景使用和禁止用法说明；
- 在任务栏、开始菜单、桌面快捷方式、标题栏和系统设置应用列表中的实机检查。

图标在 16 px 必须仍能识别 L 轮廓，不能依赖渐变、阴影或内部细线才能成立。最终色板和造型需要负责人批准后再固化为品牌资产。

当前四套原创概念、尺寸初审和候选排序见 [`15-icon-concept-audit.md`](15-icon-concept-audit.md)。当前首选 A 仍是内部评审资产，不得提前写入应用清单或发布包。

## 7. 正式 UI 范围

第一个只读 MVP 垂直切片至少需要：

1. Long方格启动/恢复入口；
2. 首次引导与“尚未修改任何文件”说明；
3. 一个桌面容器及项目引用；
4. 容器创建、命名、移动、缩放、锁定和删除关系；
5. 空、加载、错误、离线、恢复和安全模式状态；
6. 托盘菜单、设置页、诊断页和退出；
7. 浅色、深色、高对比、文本缩放和减少动画；
8. 键盘、鼠标、触控和 UI Automation/Narrator 对等路径。

正式 UI 必须复用 Core/Contracts 状态，不得在视图层另建一套文件语义或布局事实。

## 8. 一键启动要求

建立正式 `LongGrid.App` 后，仓库根目录必须提供一个稳定入口，例如 `eng/Start-LongGrid.ps1`：

- 默认执行依赖检查、必要 restore/build 并启动开发版 Long方格；
- 支持 Debug/Release、架构和可选诊断参数；
- 默认不要求管理员权限，不修改真实桌面文件；
- 检测缺失 SDK/Windows 组件并给出可操作错误；
- 不静默安装依赖、证书或系统组件；
- 启动失败返回非零退出码；
- README 只保留这一条推荐启动入口，底层命令作为故障排查说明。

安装后的用户入口必须包括开始菜单项；桌面快捷方式和开机启动由用户选择，不能默认强制创建或启用。

## 9. 一键打包要求

`eng/Pack-LongGrid.ps1` 已建立内部便携 Developer Preview 链，`eng/Pack-LongGridMsix.ps1` 已建立未签名 MSIX 身份/结构链，`eng/New-LongGridSbom.ps1` 已建立固定工具版本的 SPDX 2.2 生成/验证链；进入正式安装包模式还必须：

- 固定执行 restore、format、Release build、test、覆盖率、安全探针和包结构验证；
- 生成开发 MSIX、符号、版本信息、SHA-256 和构建清单；
- 支持 x64，以及产品决策批准后的 ARM64；
- 默认产物写入明确的 `artifacts/` 子目录并可重复清理；
- 当前开发包保持未签名并明确标识；只有未来独立、可抛弃的安装测试环境在获得专门批准后才可使用测试证书；
- 正式签名只在受保护 CI/Release 环境执行，脚本和日志不得包含证书或令牌；
- 任一门禁失败时停止，不输出看似成功的安装包；
- 支持从干净克隆复现，并在 CI 上传包结构验证结果。

`-SkipTests` 等快速选项只能用于本地诊断，不得用于 Nightly/Beta/Stable 发布。

## 10. 阶段门禁

- Phase 0：确认名称、视觉方向、图标概念和 UI/动效可用性任务；不要求已有正式应用；
- 首个生产切片：建立 Design Token、正式 UI Shell、一键启动脚本和未签名开发包；
- MVP 内测：完整 UI 状态、主题/无障碍、品牌图标、自动化 UI smoke 和一键开发打包通过；
- Beta：签名、升级/降级/卸载、开始菜单/快捷方式、图标资产和多系统矩阵通过；
- Stable：品牌、商店素材、隐私、SBOM、哈希、签名和回滚全部批准。

任务栏美化、LongBar、小组件和插件市场继续按 P1/P2 管理，不得阻塞 Long方格核心桌面整理 UI 的完成。
