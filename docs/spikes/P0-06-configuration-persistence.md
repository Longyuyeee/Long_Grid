# P0-06：版本化配置原子写入、备份与损坏恢复

执行日期：2026-07-30 至 2026-07-31

结果：**Conditional Pass（应用级原子替换、备份恢复、安全模式、四检查点子进程强杀、跨进程单写租约、确定性示例迁移回滚、只读文件恢复、受控磁盘满注入、创建/替换/内容写入/父目录继承 ACL 语义和目录只读属性语义通过；1,000 次强杀、断电、真实卷磁盘满/只读与完整权限矩阵仍待关闭）**

## 1. 目标

验证 Long Grid 的配置持久化基线：

1. 每个文档包含并校验 `schemaVersion`；
2. 新内容先写入同目录 `.new` 临时文件；
3. 临时文件完成序列化、落盘刷新和反序列化校验后才可提交；
4. 已有主文件通过替换操作提交，同时保留上一版 `.bak`；
5. 主文件损坏时读取最近有效备份，但不自动覆盖损坏证据；
6. 主文件和备份均无效时进入安全模式，不返回空配置冒充成功；
7. 中断留下的 `.new` 文件不参与启动加载；
8. 未识别 JSON 字段可在往返保存后保留；
9. 过大的配置在反序列化前被拒绝。
10. v1→v2 示例迁移确定、不可原地修改，失败不发布且成功后保留 v1 备份。
11. 多进程同时保存时只有一个写者，争用者不破坏暂存文件，持有者终止后可恢复写入。
12. 主文件、备份、遗留 `.new` 或 `.lock` 被设置为只读时不得误报提交成功，恢复文件属性后可继续写入。
13. 不填满用户磁盘，通过确定性故障注入验证部分临时写入、刷新前和提交前磁盘满均不发布候选版本，清理后可重试。
14. 临时目录拒绝当前用户新建文件时保存失败且不改变已提交版本；恢复原 DACL 后可继续写入，不申请管理员权限。
15. Windows 目录 `FileAttributes.ReadOnly` 不得误判为写权限拒绝；属性存在时以真实保存结果为准，恢复原属性后仍可写入。
16. 同时拒绝主/备份文件 `Delete` 和父目录 `DeleteSubdirectoriesAndFiles` 时，完整候选不得越过 `File.Replace` 提交边界；恢复三处 DACL 后可重试。
17. 仅拒绝现有主文件的 `WriteData`、保留删除/替换授权时，原子替换仍应提交完整候选、保留上一版备份与目标拒绝 DACL；恢复原 DACL 后可继续写入。
18. 父目录新增仅对子文件继承的 `Delete` 拒绝，并同时拒绝父目录 `DeleteSubdirectoriesAndFiles` 时，现有主/备份与新建 `.new` 必须获得继承规则；候选不得发布，恢复 DACL 后遗留暂存可被下一次保存清理。

探针只写入自动创建并最终清理的临时沙箱，不读取或修改真实 Long Grid 配置、桌面文件或用户文档。

## 2. 需求与 API 合同

本探针对齐：

- PRD 场景 4：保存中终止后加载最近有效配置；
- 架构可靠性链：`new → flush → 校验 → 原子替换 → 备份`；
- 质量基线：确定性迁移、至少一个有效备份、损坏后安全模式；
- 开发流程：持久化属于 R2，需要设计、集成测试和受控矩阵。

实现采用官方 .NET API：

- [`FileStream.Flush(Boolean)`](https://learn.microsoft.com/dotnet/api/system.io.filestream.flush) 的 `flushToDisk: true` 用于刷新中间文件缓冲；
- [`File.Replace`](https://learn.microsoft.com/dotnet/api/system.io.file.replace) 用同卷临时文件替换主文件，并创建或更新上一版备份。

这里的“原子”只描述同一文件系统支持下的替换提交边界，不承诺所有存储设备在突然断电时具有相同耐久性。生产实现仍需要真实强杀、断电和文件系统矩阵。

## 3. 状态合同

加载结果只有四种：

| 状态 | 含义 | 调用方动作 |
|---|---|---|
| `Missing` | 主文件和备份均不存在 | 进入首次启动，不写入默认配置直到用户确认 |
| `LoadedPrimary` | 主文件有效 | 正常启动 |
| `RecoveredFromBackup` | 主文件无效、备份有效 | 加载备份并提示恢复；保留损坏主文件 |
| `SafeMode` | 存在配置文件但没有有效版本 | 进入安全模式，禁止空配置覆盖现场 |

失败原因使用有限枚举，不在默认输出中包含文件路径、配置内容或异常消息。

## 4. 写入顺序

```text
校验内存文档
  → 获取同目录 .lock 独占句柄
  → 清理上次遗留的 .new
  → 同目录创建 .new
  → JSON 序列化
  → FlushAsync + Flush(flushToDisk: true)
  → 从 .new 重新反序列化并校验
  → File.Replace(.new, primary, .bak)
  → 清理未提交的 .new
```

首次保存没有旧主文件时使用同目录 `File.Move` 提交。已有备份不在提交前删除；`File.Replace` 负责更新备份，从而避免人为制造“主文件尚未替换、旧备份已经消失”的窗口。

`.lock` 是无内容的常驻协调文件，存在本身不代表被锁定；只有 `FileShare.None` 的打开句柄表示写租约。写入争用快速返回有限错误，不等待或偷删其他写者的 `.new`。读句柄使用 `FileShare.Delete`：替换期间已打开的读者继续读取旧快照，替换后的新读者读取新主文件。

## 6. 审计边界

已验证：

- 提交前内存文档和暂存文件均经过 schema/结构校验；
- 临时文件、主文件和备份位于同一目录；
- 失败注入前后始终存在可识别的有效版本或明确安全模式；
- 加载备份不会静默覆盖损坏主文件；
- 普通保存拒绝覆盖已损坏主文件或安全模式现场，修复必须走未来的显式确认入口；
- 迁移步骤按相邻版本注册，始终操作深拷贝；同一源产生相同结果，三处失败注入不改变源文件或已提交配置；
- 成功发布 v2 后保留 v1 备份；v2 损坏时仍可读取 v1，未来版本和未知字段冲突不会被静默覆盖；
- 独占写租约覆盖暂存、校验和提交全过程；争用者不删除持有者文件，旧读者与新读者分别获得完整旧/新版本；
- 临时沙箱内主文件、备份、遗留 `.new` 和 `.lock` 的 Windows 只读文件属性都会阻止提交；失败时主文件和备份字节不变，恢复属性后可继续提交；
- 受控磁盘满注入不消耗卷剩余空间：首次保存部分写入失败后保持 `Missing`，已有配置在部分写入、刷新前和提交前失败时主/备份字节不变，`.new` 被清理且下一次保存成功；
- Windows 临时沙箱的 DACL 只增加当前用户 `CreateFiles` 拒绝，不拒绝读取、删除或修改权限；保存失败后主/备份字节不变，`finally` 恢复原 DACL，并按 SID、类型、权限、继承与传播标志组成的规范化规则集合比较，随后重试成功；失败只输出固定错误码，不输出 SID 或路径；
- Windows 目录 `FileAttributes.ReadOnly` 是目录自定义/Explorer 语义，不是写访问控制；属性存在时 `.new`、`File.Replace` 和 `.bak` 正常工作，生产代码必须以实际 I/O/ACL/卷错误判断可写性；
- 替换权限矩阵同时拒绝主/备份的 `Delete` 与父目录的 `DeleteSubdirectoriesAndFiles`，堵住 Windows 删除授权的两条路径；候选完成暂存后替换失败，主/备份字节不变、`.new` 被清理，三处 DACL 规则恢复后重试成功；
- 仅对现有主文件拒绝当前用户 `WriteData` 不会阻止本实现的 `File.Replace`：候选成为完整主配置，原主配置成为正确备份，替换后的主文件仍保留该拒绝规则；因此“不能改写文件内容”不能推导为“不能原子替换”，删除与父目录替换权限必须单独验证；
- 父目录新增 `ObjectInherit + InheritOnly` 的当前用户 `Delete` 拒绝后，现有主/备份及随后创建的 `.new` 均以 `IsInherited=true` 获得规则；再拒绝父目录 `DeleteSubdirectoriesAndFiles` 会让替换与暂存清理同时失败，但主/备份保持不变且 `.new` 是可解析的完整候选，恢复父目录和子文件 DACL 后下一次保存会先清理遗留文件并成功提交；
- 无效、空、超大和不支持 schema 的文档不会作为成功配置返回；
- 探针输出不包含沙箱路径或配置内容。

尚未验证：

- 目标 1,000 次真实进程强杀；当前只有 40 次本地和每次 CI 8 次证据；
- 物理断电、磁盘缓存丢失、真实卷配额/空间耗尽、`File.Replace` 内部空间不足和只读卷/挂载点；
- 非 NTFS 权限模型，以及 ACL 修改期间进程终止；创建/替换/内容写入/父目录继承语义通过不代表完整权限矩阵通过；
- OneDrive、网络盘、FAT/exFAT 和非本地文件系统；
- 完整应用单实例激活、写入排队/退避策略和高并发长时间压力；
- 正式产品 v2 schema、多步迁移链、降级兼容期限和大配置迁移性能；
- 备份轮转、诊断提示和用户确认后的修复写回；
- 真实生产 `LongGrid.Infrastructure` 模块。

因此本结果保持 Conditional Pass，不能将探针程序集作为产品配置存储直接发布。
