# P0-06：版本化配置原子写入、备份与损坏恢复

执行日期：2026-07-30

结果：**Conditional Pass（应用级原子替换、备份恢复、安全模式和四检查点子进程强杀通过；1,000 次强杀、断电与迁移回滚仍需受控矩阵）**

## 1. 目标

验证 Long Grid 的配置持久化基线：

1. 每个文档包含并校验 `schemaVersion`；
2. 新内容先写入同目录 `.new` 临时文件；
3. 临时文件完成序列化、落盘刷新和反序列化校验后才可提交；
4. 已有主文件通过替换操作提交，同时保留上一版 `.bak`；
5. 主文件损坏时读取最近有效备份，但不自动覆盖损坏证据；
6. 主文件和备份均无效时进入安全模式，不返回空配置冒充成功；
7. 中断留下的 `.new` 文件不参与启动加载；
8. 未识别 JSON 字段可在往返保存后保留；
9. 过大的配置在反序列化前被拒绝。

探针只写入自动创建并最终清理的临时沙箱，不读取或修改真实 Long Grid 配置、桌面文件或用户文档。

## 2. 需求与 API 合同

本探针对齐：

- PRD 场景 4：保存中终止后加载最近有效配置；
- 架构可靠性链：`new → flush → 校验 → 原子替换 → 备份`；
- 质量基线：确定性迁移、至少一个有效备份、损坏后安全模式；
- 开发流程：持久化属于 R2，需要设计、集成测试和受控矩阵。

实现采用官方 .NET API：

- [`FileStream.Flush(Boolean)`](https://learn.microsoft.com/dotnet/api/system.io.filestream.flush) 的 `flushToDisk: true` 用于刷新中间文件缓冲；
- [`File.Replace`](https://learn.microsoft.com/dotnet/api/system.io.file.replace) 用同卷临时文件替换主文件，并创建或更新上一版备份。

这里的“原子”只描述同一文件系统支持下的替换提交边界，不承诺所有存储设备在突然断电时具有相同耐久性。生产实现仍需要真实强杀、断电和文件系统矩阵。

## 3. 状态合同

加载结果只有四种：

| 状态 | 含义 | 调用方动作 |
|---|---|---|
| `Missing` | 主文件和备份均不存在 | 进入首次启动，不写入默认配置直到用户确认 |
| `LoadedPrimary` | 主文件有效 | 正常启动 |
| `RecoveredFromBackup` | 主文件无效、备份有效 | 加载备份并提示恢复；保留损坏主文件 |
| `SafeMode` | 存在配置文件但没有有效版本 | 进入安全模式，禁止空配置覆盖现场 |

失败原因使用有限枚举，不在默认输出中包含文件路径、配置内容或异常消息。

## 4. 写入顺序

```text
校验内存文档
  → 清理上次遗留的 .new
  → 同目录创建 .new
  → JSON 序列化
  → FlushAsync + Flush(flushToDisk: true)
  → 从 .new 重新反序列化并校验
  → File.Replace(.new, primary, .bak)
  → 清理未提交的 .new
```

首次保存没有旧主文件时使用同目录 `File.Move` 提交。已有备份不在提交前删除；`File.Replace` 负责更新备份，从而避免人为制造“主文件尚未替换、旧备份已经消失”的窗口。

## 6. 审计边界

已验证：

- 提交前内存文档和暂存文件均经过 schema/结构校验；
- 临时文件、主文件和备份位于同一目录；
- 失败注入前后始终存在可识别的有效版本或明确安全模式；
- 加载备份不会静默覆盖损坏主文件；
- 普通保存拒绝覆盖已损坏主文件或安全模式现场，修复必须走未来的显式确认入口；
- 无效、空、超大和不支持 schema 的文档不会作为成功配置返回；
- 探针输出不包含沙箱路径或配置内容。

尚未验证：

- 目标 1,000 次真实进程强杀；当前只有 40 次本地和每次 CI 8 次证据；
- 物理断电、磁盘缓存丢失、磁盘满、只读目录和 ACL 变化；
- OneDrive、网络盘、FAT/exFAT 和非本地文件系统；
- 多进程并发写入和单实例锁；
- schema v1→v2 的不可变迁移、失败回滚和未知嵌套字段策略；
- 备份轮转、诊断提示和用户确认后的修复写回；
- 真实生产 `LongGrid.Infrastructure` 模块。

因此本结果保持 Conditional Pass，不能将探针程序集作为产品配置存储直接发布。
