# Long Grid 质量、安全与隐私基线

## 1. 安全边界

Long Grid 会接触桌面文件元数据、快捷方式和窗口信息，属于高信任本地软件。最低承诺：

- 默认以普通用户权限运行。
- 不注入 Explorer 或其他进程，不安装驱动。
- 不绕过 Windows ACL，不静默申请管理员权限。
- 不上传文件内容、文件名、完整路径、窗口标题或缩略图。
- 网络模块可识别、可关闭，不影响核心整理功能。

## 2. 文件操作安全

所有副作用使用统一 `IFileOperationService`：

- 先生成计划并展示源、目标、冲突和预计结果。
- 执行前再次验证路径、权限、磁盘和目标是否变化。
- Windows 适配器优先使用 Shell `IFileOperation`，保留系统进度、错误和回收站语义。
- 优先使用系统可恢复操作；跨卷移动按复制 + 校验 + 删除处理。
- 遇到覆盖、符号链接/重解析点、网络路径和云占位文件时默认停止。
- 操作日志记录匿名 ID 和结果；诊断导出时路径脱敏。
- 单次批量操作要么可完整回滚，要么明确报告部分成功。

MVP 不执行无人确认的自动真实文件移动。规则默认只改变 Long Grid 内的视觉归属；若启用托管目录，真实移动必须逐次或按单条规则明确授权，并记录可撤销边界。

## 3. 配置与迁移

- 每个文档包含 `schemaVersion`。
- 迁移函数是确定性、可测试、不可原地破坏的。
- 始终保留至少一个最近有效备份。
- 加载失败进入安全模式，不用空配置覆盖损坏文件。
- 导入前校验大小、深度、类型、路径和未知扩展。
- 导出必须先给出不含路径与内容的有限预览，确认后才请求本地目标授权；目标采用唯一文件名、同目录暂存、正式合同复读和不覆盖发布。
- 损坏/旧配置证据默认只读；清单必须有界并隐藏文件名、路径、随机标识和内容。原文导出必须逐项选择、明确敏感内容警告、确认后授权目标、限制大小、复读完整性且保留来源；保留期限与清理需要独立确认和审计。

## 4. 插件边界

插件不进入 MVP。未来若开放：

- 清单声明权限：文件元数据、网络、窗口信息、通知等。
- 默认进程外运行并设资源上限。
- 插件不能直接访问核心配置文件。
- 签名、来源和权限在安装前明确展示。
- 禁止插件模拟“Long Grid 官方”或静默扩大权限。

## 5. 隐私

### 默认收集

无远程遥测。仅保存本地运行所需的配置、布局、规则和轮转日志。

### 可选诊断

- 崩溃报告必须显式选择加入。
- 发送前展示字段和附件。
- 对路径、用户名、窗口标题和文件名做不可逆脱敏。
- 提供数据清除、导出和保留周期说明。

### 若未来提供同步

必须单独完成数据流图、威胁模型、密钥恢复方案、删除机制和跨境/地区合规审查；同步不能成为本地核心功能的前置条件。

## 6. 测试矩阵

### 系统

- Windows 10/11 的受支持版本。
- x64，及产品决定支持时的 ARM64。
- 普通用户、管理员账户、企业策略限制账户。
- Explorer 重启、注销、休眠、快速启动、远程桌面。

### 显示

- 单屏、双屏、三屏。
- 横竖屏混用、负坐标、主屏切换。
- 100%、125%、150%、200%、250%、300%、400% DPI。
- 分辨率切换、HDR、自动隐藏任务栏、投影模式。
- 默认日志和诊断包不得包含显示器 PNP ID、Device Key、adapter LUID、source/target ID、source GDI name、EDID、设备路径、序列号式字段或可关联的路径/拓扑散列。

### 文件系统

- NTFS、本地盘、可移动盘、网络盘。
- OneDrive/其他云占位符。
- 长路径、Unicode、emoji、RTL、大小写差异。
- 失效快捷方式、只读目录、拒绝访问、磁盘满。
- 重解析点、符号链接和循环。

Windows 目录的 `FileAttributes.ReadOnly` 不等同于写权限拒绝，不能单独作为“只读目录”判定。矩阵中的只读必须由实际 ACL、共享/卷策略或 I/O 失败证明，并验证应用不会发布部分结果。

Windows 文件的内容写入权与原子替换权也不是同一权限边界：拒绝现有文件 `WriteData` 时，若文件删除或父目录替换授权仍存在，`File.Replace` 仍可能成功。权限测试必须分别覆盖内容改写、文件 `Delete`、父目录 `DeleteSubdirectoriesAndFiles`，并验证替换后目标 DACL。

父目录 ACL 变化还会把可继承规则传播到已有和新建子文件。若继承的文件 `Delete` 拒绝与父目录 `DeleteSubdirectoriesAndFiles` 拒绝同时存在，失败清理也可能暂时无法删除完整 `.new`；加载器必须忽略该暂存文件，权限恢复后的下一次保存必须先安全清理再提交。

进程终止不会自动回滚已经写入文件系统的 ACL，但内核会释放该进程持有的独占写租约。恢复流程必须把“权限元数据仍受限”和“写者仍存活”作为两个独立状态处理：先保留并读取最近有效主配置，显式恢复权限后再清理完整暂存并重试，不能因锁句柄已释放就发布遗留 `.new`。

写租约排队不得默认无限等待或忙等。默认仍应快速失败；显式重试必须具备严格总超时、递增且封顶的间隔和取消传播，并在获得租约前不得触碰 `.new` 或已提交文件。探针级退避只定义存储互斥边界，不替代产品层的保存合并、公平性、进度提示或用户取消设计。

自动保存合并采用 latest-wins 时，被合并请求必须等待覆盖它的最新状态真正落盘后才能报告完成；协调器在入队时取得独立快照，调用方取消默认只取消自身等待，不能悄悄撤销其他调用方共享的最新状态。单批失败必须向该批等待者传播并允许后续批次继续；完成入口原子停止接收新请求并排空已接受批次，有界等待超时只取消退出等待，不得中断后台提交。真实应用关闭生命周期接线、UI 进度和跨进程公平性仍需产品合同。

### 交互与无障碍

- 键盘-only、触控、鼠标、多种输入法。
- Narrator、文本缩放、高对比度、减少动画。
- 全局快捷键冲突、游戏全屏、演示模式。

## 7. CI 质量门禁

本节定义最低质量门槛；具体 PR、Nightly、Beta、Stable 流程和风险分级遵循[开发流程与交付规范](10-development-workflow.md)。

每个 PR：

- restore/build/test 可重复通过，格式和静态分析无新增告警；
- Core 行覆盖率不低于 90%，分支覆盖率不低于 75%；
- 配置持久化缩减矩阵、文件操作安全沙箱和缩略图 worker 隔离矩阵通过；
- 缩略图格式矩阵必须使用自有样本和精确 HRESULT 分类；handler 已注册、模块存在或 Media Foundation decoder 可枚举仍不等于 Shell 可提取，`WTS_E_FAILEDEXTRACTION` 只允许对固定受控 HEIC/AVIF 样本触发安全降级；
- 依赖漏洞门禁通过，并上传 TRX 与 Cobertura 证据。

许可证扫描、CodeQL、临时安装包和打包验证仍是发布流水线待办，不能因当前 PR CI 通过而视为已经完成。

每日/发布前：

- UI 冒烟、多 DPI 截图差异。
- 布局随机化/属性测试。
- 强杀与配置恢复测试。
- 长时间资源泄漏测试。
- 安装、升级、卸载和回滚。
- 生成 SBOM 并对二进制签名。

## 8. 发布阻断条件

出现以下任一情况不得发布：

- 可导致用户文件丢失、误删除或不可逆移动。
- 配置损坏后无恢复路径。
- 普通使用要求管理员权限。
- 已知高危依赖漏洞。
- 未经同意发送敏感数据。
- 多显示器切换后大规模丢失布局。
- 显示器映射歧义时仍自动或部分提交布局。
- 新显示变化已经开始后仍提交旧代次恢复计划。
- 批量窗口应用失败或结果不一致后仍宣称恢复成功，或未经验证就丢弃回滚快照。
- 回滚失败后继续自动重试窗口移动，造成布局震荡或覆盖诊断现场。
- Win32 批量适配器忽略 `DeferWindowPos` 返回的新句柄、排队失败后仍调用 `EndDeferWindowPos`，或提交时意外改变焦点/Z-order。
- `SetWindowRgn` 成功后继续读取/删除已转移的 HRGN，或 Region 部分应用失败后留下整窗输入遮挡。
- Bounds/Region/DComp/UIA 复合事务未先关闭输入、未捕获全层快照、遗漏失败层本身的补偿、在全部 Restore 完成前验证跨层状态，或补偿失败后未保持输入关闭并隐藏宿主。
- 显示/设备/电源/会话动态矩阵缺少预期公开事件、最终未回到稳定 Ready、采样失败或资源未闭环，却仍标记为 Pass；`Inconclusive` 不得改写成通过。
- 自定义 DesktopHost 项目可由鼠标操作却没有同等键盘/UIA Pattern，选中状态与真实键盘焦点不可区分，或 UIA 调用未发对应事件。
- 隐藏消息窗口出现在 Alt+Tab/任务栏、抢焦点，或 WTS/Timer/窗口类未成对注销。
- 在线程池工作线程反复创建 DPI 探测 HWND，导致 USER 消息队列上限随线程数漂移。
- 安装包未签名或升级无法回滚。
