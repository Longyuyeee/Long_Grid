# Long方格正式方格卡片快速折叠审计

## 1. 目标与竞品对齐

iTop Easy Desktop、Fences 一类桌面分组产品的高频操作通常就近放在分组对象上。Long方格 Stage 94 在 Stage 91“卡片直达管理”的基础上，为每个正式方格卡片增加标准“折叠方格 / 展开方格”按钮，减少进入管理区后再次定位和提交的步骤。

本切片只改善正式工作区的高频配置交互，不宣称已经控制桌面层窗口，也不移动、隐藏或重排真实桌面文件。

## 2. 准入与陈旧状态

快速操作不能只相信模板传回的列表位置。`ProductWorkspaceContainerQuickCollapsePolicy` 同时复核：

- 请求序号必须为正数；
- 当前只读工作区与当前编辑候选中必须各有且仅有一个相同序号；
- 两份快照都必须处于未锁定状态；
- 两份快照的当前折叠状态必须一致。

缺失、重复、锁定或刷新造成的不一致均默认拒绝，且不退化为按索引猜测。通过后只使用策略返回的候选索引和反向折叠值。

## 3. 提交、无障碍与隐私边界

按钮复用既有 `ProductWorkspaceContainerCommitAction.SetCollapsed`、共享 edit revision、v1 投影、唯一保存控制器和工作区重建路径，没有第二套写入实现。锁定卡片在展示层禁用，提交层仍保留锁保护。

重复按钮具有随状态变化的可访问名称，但不分配重复 `AutomationId`，因此权威 UI 合同保持 137-ID。结果继续通过既有 live region 提供有限机器状态，不暴露容器 ID、路径、配置指纹或原始错误。

## 4. 安全结论

- `DesktopFilesChanged=False`：不调用文件移动、删除、重命名或 Shell 写入；
- 不调用 DesktopHost、HWND、任务栏或系统设置能力；
- 该状态目前只影响正式配置，真实桌面容器视觉折叠仍需后续获批的 DesktopHost 产品接线；
- 自动测试不能替代 #19 的键盘/Narrator/高对比/缩放人工矩阵，也不能替代 #20/#23/#24 外部证据。

## 5. 验证结果

- Core 策略 11 项定向测试通过，覆盖成功折叠、成功展开、重排候选、非法序号、缺失、重复、锁定、状态不一致和空参数；
- Release 构建为 0 warning / 0 error；全量 577 项测试通过；
- 覆盖率为 line 91.38%、branch 80.89%，高于 90% / 75% 门槛；
- UI 源码合同通过，验证显式点击、状态/可访问名称绑定、无重复 AutomationId、双快照策略和配置专用提交，权威计数保持 137；
- 启动链、VSTest 挂起诊断、格式、diff whitespace 与依赖漏洞门禁通过；真实交互桌面人工证据未在本切片伪造。

结论：该切片在不扩大桌面文件与窗口权限的前提下，完成了竞品式对象就近快速折叠，并通过双快照一致性避免陈旧卡片误提交。
