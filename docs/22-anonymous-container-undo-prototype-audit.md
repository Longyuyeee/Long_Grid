## 1. 本切片为何只做内存原型

PRD 要求容器可创建、命名、移动、缩放和删除，并且删除容器只能移除 Long方格关系，绝不能删除磁盘文件。交互审计还要求首次用户能快速创建容器，并在动作发生后立即看到撤销入口。

当前仓库尚无经过负责人和 ADR 评审的生产容器 schema、持久化仓库或 DesktopHost 接线。若此时在 Core 中固化临时实体，会把低保真验证误写成产品合同。因此本切片把状态严格留在 `LongGrid.App` 当前进程中，只验证创建、反馈和撤销心智模型，不形成存储兼容承诺。

## 2. 已实现的用户流程

`首次整理`页新增“练习创建第一个方格”：

1. 默认提供匿名名称，用户也可输入最多 40 个字符；名称不会成为文件夹名；
2. 空白名称被阻止，并进入 `PracticeContainerNameRequired`；
3. 创建后显示“0 个匿名引用 · 仅内存”的可见方格，进入 `PracticeContainerCreated`；
4. 创建后立即启用撤销按钮，并提供 `Ctrl+Z` 加速键；
5. 撤销后隐藏关系、清空显示值并禁用重复撤销，进入 `PracticeContainerUndone`；
6. 状态文本明确说明没有读取、移动或删除文件。

创建同名方格会替换当前练习预览，不产生列表或磁盘对象。这是单步低保真行为，不是正式 CRUD。

## 3. 竞品与需求对齐

- 吸收 iTop 的低门槛、可直接完成的首次动作；
- 吸收 Fences 的“创建后立即看到容器”反馈；
- 吸收 PowerToys 的明确状态与可验证后果；
- Long方格增加默认匿名数据、实时安全说明和关系级撤销，避免把视觉删除误解为文件删除。

没有复制竞品文案、图标、布局资产或付费机制。

## 4. 自动化与安全合同

- UI 结构合同覆盖 37 个唯一 AutomationId、4 个访问键和 3 个 `Polite` 状态区域；
- 结构检查固定名称上限、`Ctrl+Z` 以及创建/空名称/撤销三个机器状态；
- 真实 UIA 已复读创建后预览可见、撤销启用、撤销状态和按钮复位；
- 既有边界继续禁止 `System.IO`、Known Folder、Desktop Catalog、Shell change、DesktopHost 和 `FileOrganizationPlanner`；
- Release 构建为 0 警告、0 错误，启动链、结构合同和真实 UIA 本地通过。

GitHub CI 是本切片合并前的最终自动证据。

## 5. 仍未完成

- 没有真实容器模型、多个容器、移动、缩放、删除确认、布局持久化或活动中心；
- 没有向容器添加真实或匿名项目，也没有拖放语义；
- `Ctrl+Z` 已建立声明合同，但本轮真实 UIA 通过按钮复读同一撤销处理器，仍需 #19 人工键盘矩阵验证物理快捷键；
- 没有证明文件移动操作的系统级撤销、失败补偿或恢复；
- 五人无提示测试与负责人范围决策仍为 Pending。
