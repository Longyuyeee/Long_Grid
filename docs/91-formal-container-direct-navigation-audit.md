# Long方格正式方格卡片直达管理入口审计

> 审计日期：2026-08-11
>
> 范围：正式工作区可见方格卡片到既有方格管理选择器的显式导航
>
> 结论：只读选择与焦点切片；不提交编辑、不保存配置、不修改桌面文件、不执行 DesktopHost

## 1. 需求与竞品交互对齐

Long方格已经支持创建、重命名、锁定、折叠、外观、位置、尺寸和删除，但用户从正式工作区概览看到某个方格后，仍需返回顶部下拉框再次查找。iTop 与 Fences 值得吸收的核心不是视觉复制，而是从用户当前看到的对象直接进入管理；这也对应既有交互规范的“桌面优先、直接操作、核心动作至少有鼠标和键盘替代路径”。

本切片在每个可见方格卡片底部增加标准“查看并管理此方格”按钮。用户显式点击或键盘调用后，只按有限序号选择既有 `ProductWorkspaceContainerEditSelector` 并请求程序化焦点。按钮本身不执行重命名、锁定、折叠、外观、位置、删除或任何保存动作；所有编辑仍要求用户在既有管理区再次明确操作。

## 2. 准入、陈旧状态与失败关闭

`ProductWorkspaceContainerNavigationPolicy` 同时验证请求序号在当前只读工作区中恰好出现一次，并在当前编辑候选中恰好出现一次；返回的是候选当前索引，不假定筛选结果顺序等于编辑候选顺序。序号非正数、工作区缺失或重复、候选缺失或重复、空集合和陈旧映射统一返回 `-1`。

App 只消费 `_workspaceRead` 与 `_containerEditor` 的 presentation 序号。拒绝路径不改变既有选择、不移动焦点、不尝试修复状态，并通过现有 live region 报告有限拒绝状态。成功路径先选择匹配候选，再记录真实焦点结果；焦点失败不会被误报为成功。

## 3. 无障碍、隐私与响应式

- 使用标准 WinUI `Button`，支持 Tab、Space、Enter 与指针调用，不增加自定义手势。
- 每个重复按钮使用绑定的可访问名称；由于同一模板会实例化多次，刻意不分配重复 AutomationId。
- 权威唯一 AutomationId 合同保持 137-ID；已有方格管理选择器仍是唯一焦点目标。
- live-region 机器状态只包含有限序号、焦点结果、`Changed=False` 和 `DesktopFilesChanged=False`，不包含名称、路径、稳定 ID 或异常原文。
- 按钮位于现有卡片内部并允许内容自然换行/纵向扩展；Narrator、高对比、200% 文本缩放、紧凑宽度和触控目标真实结果仍需专用账户复核。

## 4. 安全边界与非目标

本轮不读取文件内容，不枚举或刷新 Catalog，不取得持久化 target、路径或 workspace identity，不写配置、不递增 revision、不创建撤销令牌，也不移动、删除、重命名或打开桌面文件。它不调用 DesktopHost、不修改系统设置，也不扩大任务栏、小组件/Long助手插件、Folder Portal、搜索或真实文件整理范围。

卡片直达只降低“概览对象 → 既有管理区”的导航成本；它不是桌面原生容器、拖放、Peek、标签页或自动整理执行。

## 5. 自动证据与外部门禁

Core 定向测试覆盖候选重排后的正确索引、非正数、工作区缺失/重复、候选缺失/重复和空引用参数。源码合同锁定序号绑定、标准显式 Click、重复按钮无 AutomationId、唯一匹配策略、选择现有管理候选、程序化焦点、拒绝状态和零修改声明。

Release 全解决方案构建为 0 warning / 0 error；单份 Stage 91 Cobertura 下 566/566 测试通过，行覆盖率 91.34%（16464/18024）、分支覆盖率 80.70%（4732/5864），高于 90%/75% 门槛。启动、Issue #19/#20/#23/#24、BSA、137-ID UI、干净会话和单实例安全入口通过，并诚实保持人工结论 Pending；配置持久化 20 场景和依赖漏洞门禁通过。文件操作安全探针保持 `ConditionalPass`，真实 Explorer 撤销、跨卷、ACL、云占位符等仍需受控测试；缩略图 worker 也保持 `ConditionalPass`，隔离、清理和资源预算通过，但 AppContainer 提取、像素传输与故障恢复仍要求产品回退。精确提交 RC 在提交后执行并记录到 PR。自动门禁不替代真实键盘、Narrator、高对比、200% 文本缩放、紧凑宽度、触控与干净账户 live UIA。

Issue #19、#20、#23、#24 继续保持 OPEN；BSA-01–BSA-05、动态显示、五人无提示测试与专用卷证据仍为 Pending。

## 6. 后续方向

优先收集外部人工、硬件和专用环境证据。若环境仍不可用，只继续有限展示交互收口，并避免通过增加相邻小功能绕过 Phase 0 门禁。真实文件整理、任务栏美化、小组件和 Long助手插件兼容继续按既定后续阶段准入。
