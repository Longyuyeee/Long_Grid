# Long方格“L + 方格”图标概念审计

日期：2026-08-03

状态：**Concept Approved for RC1 / 未批准为最终品牌资产**

关联要求：[`14-visual-branding-and-delivery-requirements.md`](14-visual-branding-and-delivery-requirements.md)

## 1. 本轮目的与边界

本轮把已经确认的“现代、扁平、简约、L 与方格结合”要求转化为四个可比较的原创 SVG 概念，提前淘汰小尺寸不可读、过度装饰或与产品语义脱节的方向。

本轮不完成商标定稿、ICO/MSIX 全尺寸生产、商店宣传图或 UI 视觉系统，也不声称已经完成法律意义上的商标可注册性检索。竞品仅用于能力和交互研究；候选没有复制 iTop Easy Desktop、Stardock Fences、Nimi Places、Windows 或其他产品的商标、截图、配色组合与现成图形。

概念总览：[`assets/brand/longfangge-icon-concepts.svg`](../assets/brand/longfangge-icon-concepts.svg)

## 2. 统一设计约束

- 画板和 `viewBox` 统一为 256 × 256，四角圆角容器使用 56 单位半径；
- 核心几何来自 3 × 3 比例或相同的模块化网格；
- L 轮廓在不依赖文字、阴影、模糊、渐变和细描边时仍须成立；
- 概念源文件只使用矢量路径、矩形和纯色，不含外链、脚本、嵌入位图或第三方字体；
- 主色探索以冷色靛蓝为中心，但颜色不作为唯一识别线索；
- 16 px 是结构验收下限，32 px 用于常见任务栏/列表预览，256 px 用于品牌评审；
- 当前颜色是候选色，不是最终 Design Token。

## 3. 候选审计

评分：5 为本轮最优，1 为明显不满足。评分只用于概念排序，不等同于用户研究或商标结论。

| 候选 | L 可读性 | 方格语义 | 16 px 可读性 | 扁平简约 | 系列扩展 | 原创风险控制 | 结论 |
|---|---:|---:|---:|---:|---:|---:|---|
| A 结构化 L | 5 | 5 | 4 | 5 | 5 | 4 | **首选，进入下一轮** |
| B 负空间 L | 3 | 4 | 2 | 4 | 3 | 4 | 保留探索，不进入生产 |
| C 开放式方格 L | 5 | 3 | 5 | 5 | 4 | 4 | 备选；用于校验 A 的轮廓强度 |
| D 模块化转角 | 4 | 4 | 3 | 4 | 3 | 4 | 暂停；整体凝聚力不足 |

### A · 结构化 L

五个白色主单元形成清晰 L，三个浅靛蓝单元表达“可整理的桌面格子”。L 和方格来自同一几何系统，最符合“不能是字母叠在九宫格上”的原始要求，也最容易延展为单色、高对比和状态图标。风险是完整模块阵列属于常见图形语言，定稿前仍要进行近似商标检索，并通过间距、圆角和缺口建立更独特的轮廓。

### B · 负空间 L

深色底和紫色面板在大尺寸下有较强视觉冲击，但 L 依赖内部负空间，右上小网格在 16 px 容易糊成噪点。它更接近“华丽”的探索边界，却牺牲了任务栏识别，不适合作为当前主方向。

### C · 开放式方格 L

实心 L 在所有尺寸下最稳，浅色底也容易融入 Windows。问题是右上三个格子与 L 的联系弱于 A，容易被理解成“L 旁边放了几个方块”，因此作为 A 的可读性基准保留，而不是首选。

### D · 模块化转角

独立模块能表达桌面项目可移动和重组，但视觉重心分散，16 px 时卫星单元难以形成稳定剪影。后续小组件或插件图标体系可以借鉴其模块语言，主应用图标暂不采用。

## 4. 色彩方向

| 角色 | 候选值 | 用途与约束 |
|---|---|---|
| Brand Indigo | `#5B5FF5` | 候选 A 的品牌底色；不得承担唯一状态含义 |
| Deep Ink | `#171A2B` | 深色中性背景或正文，不默认替代系统背景 |
| Grid Tint | `#9296F8` | 次级方格；已降低亮度权重以强化 16 px 的白色 L，高对比模式仍需实色映射 |
| Surface Light | `#F8FAFC` | 评审和浅色资产背景，不代表最终应用表面 |
| White | `#FFFFFF` | 主 L，高对比版本需服从系统颜色 |

品牌主色与 Windows 系统强调色分工：品牌色用于应用识别；选择、焦点和系统状态优先遵循系统主题与可访问性映射。正式 Design Token 必须在 UI Shell 阶段另行评审。

## 5. 小尺寸与主题判断

- A：首次渲染发现次级格子过亮会削弱白色 L，已将其从浅靛蓝降为中间色；修正后 16 px 可读性改善，下一轮仍需逐尺寸像素对齐；
- B：16 px 内部四个小孔不足 1–2 个物理像素时会失真，判定不通过首选门槛；
- C：16 px L 最清晰，但三个独立格子需要合并或减少圆角；
- D：16 px 能看到 L，但卫星方格的语义丢失，整体像离散点阵；
- 四个候选尚未完成 Windows 浅色、深色、高对比、彩色任务栏和壁纸背景的实机矩阵，因此不能标记为最终通过；
- 下一轮为 A 单独制作 16/20/24/32/48/64/128/256 px 像素校正版，并加入单色、双色、深色和高对比变体。

## 7. 决策与下一步门槛

本轮建议选择 **A · 结构化 L** 进入像素校正，C 作为轮廓可读性的对照样本；B、D 不删除，但不进入产品清单或安装包。

候选 A 只有同时满足以下条件才能升级为 Release Candidate：

1. 负责人确认造型方向与候选品牌色；
2. 16–256 px 像素校正、单色/双色/浅色/深色/高对比版本齐全；
3. 在 Windows 10/11 的任务栏、开始菜单、桌面快捷方式、标题栏和应用列表完成实机检查；
4. 使用图像近似检索和商标数据库完成独立性检查，并记录地区与检索日期；
5. 无障碍、Design Token、MSIX 资产生成和许可证清单通过仓库门禁；
6. 最终批准记录写入品牌资产 README 和开发状态文档。

在上述门槛关闭前，当前资产只能用于内部评审。
