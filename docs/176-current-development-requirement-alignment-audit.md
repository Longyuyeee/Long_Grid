## 1. 审计口径

本次不以代码量、测试数量或文档数量代替产品完成度。每项能力分为：

- `Complete`：用户可见主路径、异常、持久化、物理输入、无障碍和发布证据均通过；
- `EngineeringComplete / ProductEvidencePending`：正式工程链通过，但仍缺可见、物理、硬件或辅助技术证据；
- `InProgress`：已有生产实现，但关键用户链仍未闭环；
- `Foundation / Prototype`：只有可复用底座、探针、协议或控制中心能力；
- `NotImplemented`：产品运行时尚不存在。

协议、Schema、探针、静态 AutomationId 和隐藏窗口测试都不能单独升级为用户功能完成。

## 4. 后续扩展需求对齐

### 4.1 任务栏美化

任务栏能力在 PRD 中属于 P1 实验，不属于当前核心 MVP 阻塞项。仓库已有技术与安全审计，但没有正式产品运行时：

- 不注入或 Hook `explorer.exe`，不替换系统任务栏；
- 未来只允许按 Windows build 准入、独立开关、能力探测、失败自动恢复和“一键恢复系统默认”；
- 当前没有透明度/着色应用器、设置 UI、恢复守护或真实系统构建矩阵。

结论：**设计边界已对齐，产品功能未实现。**

### 4.2 Widgets 与 Long助手插件兼容

仓库已有 Long Widget/Long助手兼容协议、JSON Schema、示例清单和安全边界文档，但尚无 Widget Host：

- 命令插件未来可包装成快捷动作卡；只有声明 Widget Surface 的受限 Web 插件可作为桌面小组件；
- DLL、C# Script 和 Hybrid 高信任插件不得嵌入 Long方格核心进程；
- 当前缺少包发现、签名/权限验证、隔离 Web 宿主、生命周期、尺寸布局、错误卡片、资源配额、设置 UI 和真实 Long助手兼容测试。

结论：**协议准备存在，运行时兼容为 P2 Pending；不能宣称已经兼容 Long助手插件。**

### 4.3 Folder Portal、Tab 与应用工作空间

PF-040–042、PF-050 和 PF-060 仍无产品运行时。它们分别属于 V1/P1 扩展，不能抢占当前方格日常操作、自动整理、快照恢复和无障碍闭环。

## 5. 当前最重要的对齐偏差

1. **工程深度领先于用户可见宽度**：配置、安全、补偿和证据体系成熟，但桌面上的日常操作面仍不完整。
2. **控制中心能力不能替代桌面能力**：重命名、批量改归属、搜索等已有正式状态合同，但对标软件强调桌面就地操作。
3. **静态/UI 线程证据不能替代物理证据**：当前已知 WinUI 组合下可见交互和跨进程 UIA 仍被安全阻断。
4. **扩展协议不能替代扩展运行时**：任务栏审计、Widget Schema 和 Long助手协议均只代表未来边界已定义。
5. **尚未进入公开发布收尾**：许可证、签名、安装升级、人工矩阵和完整品牌资产仍是硬门禁。

## 6. 从现在到桌面管理 MVP 的开发顺序

按依赖而不是按竞品页面数量推进，仍有 7 个主要工作流：

1. PF-003D2：App 消费 Surface 会话、动态候选、pointer-up 唯一提交/补偿和键盘微调；
2. PF-003 后续门：跨显示器 DPI、物理鼠标/键盘/触控和 UIA Bounds；
3. PF-004–010：标题栏、正式项目呈现、打开/选择、Explorer 拖放、视图/搜索和统一撤销历史；
4. PF-011、PF-020–022：首次引导与自动整理规则闭环；
5. PF-030、PF-033、PF-051、PF-052：隐藏/托盘/快捷键、命名快照和多显示器场景；
6. PF-070/071：正式桌面视觉、平滑可降级动效、品牌资产、无障碍/本地化/多 DPI；
7. PF-090 与发布门：安装升级、签名、许可证、干净机器和人工/长稳证据。

任务栏实验、Portal、Tab、工作空间和 Widgets/Long助手宿主在核心 MVP 之后按 P1/P2 进入，不应改变上述主路径。
