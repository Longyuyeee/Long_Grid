## 1. 开发目标与安全边界

本切片先关闭 PF-002H 最危险的底层问题：创建新方格与引用改归属必须是同一次配置编辑，不能出现“方格创建成功但引用仍在原方格”或相反的半完成状态。

冻结语义如下：

1. 只处理 Long方格自身的显式选择快照，不读取 Explorer 原生选择；
2. 引用从一个来源方格**改归属**到新方格，不复制重复引用；
3. 不移动、重命名、删除或写入真实桌面文件；
4. 请求最多 256 项，项目 ID 必须非空、唯一、存在且已解析；
5. 来源方格必须存在且未锁定，新方格 ID 必须唯一且初始项目列表为空；
6. 任一前置条件失败时，整个请求拒绝，不提交部分状态、不推进共享编辑修订；
7. 接受路径只投影一次、提交一次，并产生可恢复完整提交前状态的指纹门控令牌。

本切片明确不包含正式 App 中的“使用选择创建”按钮、Preview 数量展示、选择快照失效处理和异步保存失败后的自动 UI 补偿。这些属于下一接线切片，不能用当前 Core/Infrastructure 能力替代。

## 2. 实现审计

### 2.1 原子 reducer

`ProductWorkspaceReducer.CreateContainerFromResolvedReferences` 在一个状态转换内完成：

- 校验来源、新容器和全部选择；
- 按来源方格中的稳定顺序取出所选引用；
- 从来源方格移除这些引用；
- 克隆新方格并写入同一批引用；
- 对最终工作区只执行一次完整校验。

方法不会先创建空方格再逐项搬运，因此中途异常不会暴露部分状态。

### 2.2 共享提交协调器

`CommitSelectedReferenceContainer` 复用现有 `ProductWorkspaceCommitCoordinator`：

- 校验请求编辑修订与共享修订一致；
- 执行最多 256 项的有限输入门；
- 调用原子 reducer，并通过正式投影器生成一个配置文档；
- 在接受路径中只调用一次 `saves.Submit(edit)`；
- 仅在提交接受后推进共享编辑修订；
- 生成包含提交前/后指纹的单次恢复令牌，拒绝陈旧或事实已变化的恢复。

当前暂时复用“批量加入恢复令牌”的完整状态恢复机制。它能正确恢复本事务，但用户可见的动作名称与 PF-002E 保存失败自动补偿仍应在 App 接线时改为专用发布事务，避免错误文案或撤回后续编辑。

## 3. 真实测试：预期、实际、差异与修正

### 3.1 真实配置文件成功与撤销

测试使用真实临时目录、两个真实文本文件、正式 `ProductConfigurationStore`、正式保存工作流和真实配置文件重载。

| 检查项 | 预期效果 | 实际效果 | 差异 |
| --- | --- | --- | --- |
| 创建事务 | 来源 `2 -> 0`，新方格 `0 -> 2` | 内存与磁盘重载均完全一致 | 无 |
| 引用目标 | 两个引用目标保持原绝对路径 | 重载后目标逐项一致 | 无 |
| 真实文件 | 内容保持 `first-original` / `second-original` | 创建和撤销后内容均未变化 | 无 |
| 一次撤销 | 恢复为单一来源方格和两个引用 | 内存与磁盘重载均恢复 | 无 |

### 3.2 真实写租约失败

测试用 `FileShare.None` 实际占用配置 `.lock` 文件，不使用伪造的“失败返回值”。

| 检查项 | 预期效果 | 实际效果 | 差异 |
| --- | --- | --- | --- |
| 保存状态 | 正式控制器进入 `Failed/WriteLeaseUnavailable` | 确实进入该状态 | 无 |
| 磁盘权威状态 | 仍为提交前单一来源方格 | 真实重载保持基线 | 无 |
| 恢复 | 释放租约后恢复令牌可提交旧状态 | 第二次真实保存成功，重载正确 | 无 |
| 真实文件 | 文件内容不变 | 保持 `keep-original` | 无 |

### 3.3 拒绝矩阵

空选择、重复 ID、缺失项目、陈旧修订和锁定来源均被真实协调器拒绝；计数工作流确认保存调用为 0，共享编辑修订不推进。该测试验证的是“拒绝无副作用”，不冒充磁盘故障测试。

### 3.4 首次门禁失败与修正

首次运行静态 UI 合同实际失败。原因是旧门禁把整个协调器内 `saves.Submit(...)` 的总次数写死；新增一个合法提交方法后，总数变化被误报成重复保存。

修正后，门禁截取 `CommitSelectedReferenceContainer` 的方法范围，并要求该范围内恰好一次 `saves.Submit(edit)`。这把检查从易碎的全文件计数改为本功能的局部行为合同。修正后合同重新通过。
