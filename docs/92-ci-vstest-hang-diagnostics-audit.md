# Long方格 CI VSTest 挂起诊断与有界失败审计

> 审计日期：2026-08-11
>
> 范围：GitHub Actions 全量测试的无活动超时、测试序列证据与隐私边界
>
> 结论：CI 稳定性与诊断切片；不修改产品、测试断言、覆盖率门槛或发布权限

## 1. 触发证据与根因边界

Stage 91 的提交 `c2de9451f7858ff5dd0dea3d52b9556168b3f3c3` 在本地完成 566/566 测试，在 PR #142 的 Windows runner 中用 11 秒完成同一测试步骤，随后 PR 全门禁通过。合并提交 `5d980ef34b8f363f61c709d5d7b3d845809402a3` 的首次 `main` CI 运行 `31459221736` 则在 VSTest 报告“1 个测试程序集匹配”后长期无输出，直到 20 分钟 job 上限取消；没有失败用例、断言堆栈、TRX 或覆盖率文件。

经明确批准对同一运行执行失败作业重跑后，第二个 runner 再次在同一 VSTest 阶段无输出，并在 20 分钟 job 上限被取消。两次尝试均只完成到 Test，后续覆盖率、安全探针、漏洞和 RC 步骤被跳过；always-upload 正常执行，但没有可定位具体测试的 TRX。现有证据只能判定“VSTest/testhost 或某个测试发生无活动挂起”，不能从无日志状态指认具体测试，也不能据此修改产品代码或放宽测试结论。

## 2. 有界诊断合同

CI 的 `dotnet test` 增加：

- `--blame-hang`：启用 VSTest 无活动检测；
- `--blame-hang-timeout 2m`：单个测试无活动两分钟即有界终止；
- `--blame-hang-dump-type none`：禁止收集测试进程内存转储；
- `TestResults/**/Sequence*.xml`：无论测试成功或失败，都允许现有 `if: always()` 证据上传步骤收集测试序列文件。

两分钟远高于当前正常的 11–16 秒全套测试时间，又显著低于 20 分钟 job 上限。超时按“无活动”而非整套固定时长计算，不会把正常持续输出的长测试误切成全局两分钟限制。

## 3. 隐私与安全

内存 dump 可能包含环境变量、令牌、临时路径或进程内对象，因此本合同固定使用 `none`，不上传 `.dmp`。Sequence XML 只用于定位测试执行序列；仓库测试继续只使用自有合成数据和临时沙箱。证据仍由 GitHub Actions 现有 artifact 生命周期管理，不增加外部网络目标、写权限、secret、OIDC、Release 上传或公开分发。

该切片不降低 90% 行覆盖率、75% 分支覆盖率、566 项测试、配置持久化、文件安全、缩略图隔离、依赖漏洞或内部 RC 门禁。挂起会更早且更可诊断地失败，绝不会被转换为通过。

## 4. 源码合同与验证

`eng/Test-LongGridCiHangDiagnostics.ps1` 对 workflow 做有限源码验证：三项 VSTest 参数和 Sequence artifact 路径必须存在，独立 `--blame-hang` 必须恰好一次，并拒绝 `mini` 或 `full` dump。CI 在全量测试前执行该合同，防止后续维护静默移除诊断或恢复敏感 dump。

提交前本地验证结果：

- 诊断源码合同：Pass，确认 2 分钟超时、禁用内存 dump、允许 Sequence 证据；
- `dotnet format --verify-no-changes`：Pass；
- Release 构建：0 警告、0 错误；
- 使用与 CI 相同的三项 blame-hang 参数完成全量测试：566/566，通过耗时约 8 秒；正常完成时 VSTest 明确不生成 Sequence 文件；
- 覆盖率：行 91.32%（16460/18024），分支 80.70%（4732/5864），高于 90%/75% 门槛；
- 配置持久化探针：20 个场景全部通过；文件操作安全与缩略图 worker 隔离探针：`ConditionalPass`，保持既有受控限制；
- 依赖漏洞门禁：未发现已知漏洞包。

最终有效性仍必须由 PR CI 和合并后 `main` CI 共同证明；若仍挂起，Sequence 证据用于锁定最后执行的测试，再单独审计并修复根因。

## 5. 需求与阶段对齐

这是 Stage 91 交付收口所需的 CI 稳定性修复，不是新增产品能力。Issue #19、#20、#23、#24、BSA、动态显示、五人无提示测试和专用卷证据继续保持原状态；任务栏、小组件/Long助手插件和真实文件整理范围不变。
