# Long方格正式方格卡片单向快速锁定审计

## 1. 目标与竞品对齐

iTop Easy Desktop、Fences 等桌面分组产品会在分组对象附近提供锁定或保护入口，降低误拖动、误编辑概率。Long方格 Stage 95 在卡片直达管理与快速折叠之后增加“锁定方格”，让用户能在当前上下文立即降低编辑权限。

本切片刻意不提供卡片级快速解锁。解锁会重新开放重命名、折叠、外观、布局、引用和删除等编辑能力，仍必须进入现有管理区显式执行。

## 2. 双快照与单向准入

`ProductWorkspaceContainerQuickLockPolicy` 只接受有限序号，并同时复核当前只读工作区与当前编辑候选：

- 两侧必须各有且仅有一个相同序号；
- 两侧都必须明确为未锁定；
- 候选顺序可以不同，不能按卡片位置猜测；
- 缺失、重复、锁定、状态不一致或非法序号全部默认拒绝。

通过后策略只返回当前候选索引。App 固定提交 `SetLocked + true`，不从模板状态计算反向值，因此该入口无法被降级为解锁。

## 3. UI、无障碍与提交路径

- 未锁定卡片显示“锁定方格”；已锁定卡片显示禁用的“方格已锁定”；
- 已锁定卡片的可访问名称说明需要在管理区显式解锁；
- 重复按钮不分配 AutomationId，权威 UI 合同保持 137-ID；
- 操作复用共享 edit revision、正式 reducer/v1 投影、唯一保存控制器和工作区重建，不新增旁路写入；
- 状态通过既有 live region 播报，不暴露容器 ID、路径、指纹或原始异常。

## 4. 权限和产品事实

- 该动作只修改 Long方格正式配置的 `IsLocked`；
- 不移动、删除、重命名或隐藏真实桌面文件；
- 不连接 DesktopHost、HWND、任务栏或系统设置；
- 在正式 DesktopHost 产品接线前，“锁定”不应被宣传为已经冻结真实桌面窗口；
- #19/#20/#23/#24、BSA、Narrator、高对比、文本缩放和紧凑布局人工证据继续保持 Pending。

## 5. 验证结果

- Core 策略 9 项定向测试通过，覆盖重排成功、非法序号、缺失、重复、任一侧锁定和空参数；
- Release 构建为 0 warning / 0 error；全量 586 项测试通过；
- 覆盖率为 line 91.41%、branch 81.03%，高于 90% / 75% 门槛；
- UI 合同通过，证明按钮状态绑定、无重复 AutomationId、双快照策略、固定 `stateValue: true` 与管理区解锁边界，权威计数保持 137；
- restore、format、diff whitespace、启动链、VSTest 挂起诊断与依赖漏洞门禁通过；PR/main CI 仍需在发布阶段独立复核。

结论：单向快速锁定吸收了竞品的对象就近保护优势，同时避免高风险快捷解锁绕过 Long方格既有锁保护语义。
