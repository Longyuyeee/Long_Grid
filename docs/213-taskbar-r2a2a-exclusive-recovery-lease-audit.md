## 1. 阶段目标与结论

R2A1 已保证任务栏恢复凭据能够原子写穿，但尚未阻止两个 App/Worker 同时 Stage、应用或恢复。本阶段交付 R2A2 的第一段 `R2A2a`：用 Windows 内核文件共享语义建立唯一恢复所有权，并把所有恢复凭据写操作绑定到仍存活的同目录租约。

- 固定锁文件 `taskbar-appearance-recovery.lock`，不保存路径、用户名、窗口句柄或任务栏状态；
- 第一个进程以读写句柄取得租约，竞争进程精确得到 `Contended`；
- Worker 崩溃或被强杀后由内核释放句柄，锁文件可以保留，下一恢复进程可重新取得所有权；
- 恢复目录或锁文件是重解析点时拒绝，打开前后都复核；
- `Stage / UpdatePhase / Clear` 必须持有同目录、仍存活的租约；`Load` 保持只读，允许监控或崩溃后的取证；
- 每次异步写操作取得操作令牌，在提交完成前钉住租约；并发 `Dispose` 必须等待，避免先释放锁、后继续写盘；
- Worker 的租约采证命令只能在显式测试环境变量下使用，正式调用无开关时退出 65 且不创建锁文件。

本阶段仍未调用任务栏写 API，没有认证 Build 26200，也没有向产品 UI 暴露清透预设。

## 3. 需求对齐与未完成边界

这一阶段直接服务“任务栏美化必须稳定、可恢复”的核心需求，没有扩展 Widget、插件、自动整理、教程页或新的导航。唯一租约解决并发 App、旧 Worker、启动恢复器互相覆盖凭据的风险，是原生写入前必须完成的安全条件。

尚未完成：

- 没有原生 `SystemDefault / Clear` 应用器；
- 没有启动时消费遗留凭据并恢复 Explorer 的正式 Worker 命令；
- 没有任务栏像素变化、Explorer 重启、卸载恢复证据；
- Build 26200 仍为 `DeniedNoCertifiedBuild`；
- 当前机器缺少创建真实符号链接的权限，因此重解析攻击仍是矩阵 Pending。

下一唯一项是 `TASKBAR-R2A2b`：在 Worker 内建立失败关闭的原生适配器和启动恢复执行器。适配器必须先取得本阶段租约、加载遗留凭据并重新探测 Explorer；未认证 build 只允许返回拒绝，不能调用写 API。实际 Clear/恢复只有在可丢弃 Windows 认证矩阵中取得任务栏像素、窗口身份、Explorer 重启和强杀前后证据后才能加入白名单。
