# Long方格已验证备份接受与损坏证据归档审计

审计日期：2026-08-04

基线：`main` / `fe13041` + Issue #24 备份接受增量分支

结论（本历史切片当时）：**Explicit backup acceptance pass / SafeMode reset not implemented in this slice / Real-volume evidence pending / Issue #24 保持 OPEN**。SafeMode 空白安全重置已由后续切片完成，当前状态见 [`38-safe-mode-reset-audit.md`](38-safe-mode-reset-audit.md)。

## 1. 本轮目标与范围

本切片只关闭一个可完整证明的恢复动作：当正式 Store 已经判定主配置不可用、备份通过完整产品合同校验时，用户可以通过二次确认把该备份接受为主配置。

本轮不实现 SafeMode 重置、不自动接受备份、不删除备份、不清空损坏文件、不接入普通产品状态自动保存，也不执行 I24-01/I24-02 真实卷操作。

## 2. 写入前置条件

`ProductConfigurationStore.RecoverAsync` 只有同时满足以下条件才允许进入写路径：

1. 请求动作是有限枚举 `AcceptValidatedBackup`；
2. 请求携带 `UserConfirmed: true`；
3. 写锁前预检为 `RecoveredFromBackup`，无恢复状态时不创建目录或锁文件；
4. 取得正式有界跨进程写租约；
5. 锁内复检仍为 `RecoveredFromBackup`，防止确认后状态变化；
6. 备份复制到独立 `.recovery.new` 后再次通过正式合同校验和落盘刷新。

取消确认、状态不匹配、写租约超时、调用方取消或 I/O 失败都不会归档、覆盖或删除主配置。

## 3. 原子接受与证据保留

成功路径不直接修改备份。Store 把有效备份逐字节复制到同目录恢复暂存文件，复读校验后使用一次 `File.Replace`：

- 恢复暂存文件成为新的主配置；
- 原损坏主配置成为唯一随机后缀的 `.damaged.*` 证据；
- 原 `.bak` 保持字节不变；
- `.recovery.new` 在正常、异常和取消路径均执行尽力清理；
- 公开结果只包含有限动作与“损坏主配置已归档”布尔值，不返回路径、文件名、配置 Document 或原始异常。

该原子性仍是同目录应用级边界，不等同于断电、非 NTFS、真实只读卷或卷耗尽耐久性结论。

## 4. 交互与可访问性

- “检查并接受备份”按钮默认折叠，只在 `RecoveredBackupReadOnly` 状态显示；
- 对话框明确说明会写入配置目录、保留损坏证据、保留原备份且无法在 Long方格内自动撤销；
- 默认按钮是“取消”，只有 `ContentDialogResult.Primary` 才调用正式恢复入口；
- 执行期间按钮禁用，成功后横幅报告备份已接受和证据已归档；
- 失败只映射确认缺失、状态变化、写租约占用和有限 I/O 分类，不显示路径或原始异常；
- UI Automation 状态区分执行中、成功归档和有限失败。

结构 UI 合同现覆盖 62 个 AutomationId。上一切片已证明当前桌面会话的 WinUI UIA Provider 在 `main` 基线也会返回 `E_UNEXPECTED`；本轮不通过真实 `%LOCALAPPDATA%` 构造损坏配置来伪造端到端通过，因此本机视觉/真人确认仍继承 `Inconclusive/Pending`，等待隔离用户配置环境复核。

## 5. 自动证据

- 144/144 自动测试通过；
- 行覆盖率 91.66%（1725/1882），分支覆盖率 80.32%（457/569），超过 CI 的 90%/75% 门槛；
- 成功路径验证新主配置等价于已验证备份、原备份字节不变、损坏主配置字节完整归档；
- 未确认请求验证主备字节不变、零归档、零写锁创建；
- 无恢复状态验证零存储目录创建；
- 写租约超时与调用方取消验证损坏证据不变、零归档、零恢复暂存残留；
- I/O 失败验证有限错误且异常文本不泄露路径；
- `null` 与未知动作在创建存储前被拒绝；
- UI 源码合同验证按钮默认隐藏、Primary 二次确认、取消默认焦点、正式 Store 路由和脱敏状态；
- Release solution build 为 0 warning / 0 error。

## 6. 未关闭门槛与下一步

Issue #24 仍需：

1. SafeMode 下经确认的空白安全重置已由后续切片完成；仍需外部导入流程，以及多份损坏证据的查看/导出/保留/清理策略；
2. 经批准的真实产品状态保存入队、保存错误提示与重试；
3. 真实待保存/恢复写入期间的第二实例激活和关闭排空竞态矩阵；
4. I24-01/I24-02 专用卷真实证据；
5. 断电、非 NTFS、企业重定向目录和长期跨进程压力；
6. 隔离用户配置环境中的真实 UI、键盘、Narrator、高对比和文本缩放复核。

在这些证据完成前，本切片只能描述为“用户可显式接受一份已验证备份并保留损坏主配置”，不能描述为完整配置修复、自动修复或发布就绪。
