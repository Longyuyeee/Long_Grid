# 批量选择无障碍人工矩阵就绪审计

> 日期：2026-08-10
> 范围：正式 `LongGrid.App` 批量选择的人工场景拆分、安全启动链、CI 合同与结果纪律
> 审计基线：`main` / `02f7ee6`（Stage 84 已合入）
> 当前结论：**Ready to execute / Pending manual evidence**

## 1. 缺口与需求对齐

Stage 83–84 已完成键盘可达的有限批量入口、空选择复位、单次 `LiveRegionChanged` 播报和 760 DIP 紧凑重排，但这些自动化证据不能回答四类人工问题：Narrator 是否自然且只朗读一次最终状态、高对比度下焦点/选择/禁用是否可区分、200% 文本缩放是否裁切，以及视觉顺序是否与键盘/听读顺序一致。

本阶段不新增产品权限或业务功能，而是把上述未知拆成可单独执行、可恢复、不可伪造 Pass 的 BSA-01–BSA-05。该范围直接承接最初“现代 UI 必须可用、平滑且遵循 Windows 无障碍约定”的需求，也保持零桌面文件修改和零 DesktopHost 执行边界。

## 2. 会话链与安全合同

`eng/Start-LongGridBatchAccessibilitySession.ps1` 提供统一入口：

- `-ValidateOnly` 复核权威 134-ID UI 合同、8 个批量选择关键 AutomationId、两个 Polite 状态区、单次播报抑制和 760 DIP 紧凑布局源码合同；
- 真实运行必须指定一个 BSA 场景、匿名 `O1`–`O9` 操作员，并显式确认专用测试账户与恢复计划；
- 启动前后都要求零 `LongGrid.App` 进程，发现外来进程时拒绝继续且绝不终止；
- 启动器先通过统一启动链完成构建验证，再直接持有本轮产品进程句柄；15 秒内没有主窗口或启动失败时只清理本轮自有进程，正常会话等待操作员关闭后复核零残留；
- 启动器不读取桌面文件内容，不修改 Long方格配置或桌面文件，不切换系统设置，不采集证据，不写结果；
- 真实 App 会按既有产品边界只读枚举专用账户桌面第一层元数据，因此运行手册禁止使用个人桌面。

CI 新增该启动器的 `-ValidateOnly` 门禁。其成功只证明入口仍可执行，输出固定为 `PendingManualEvidence`。

## 3. 人工矩阵

| 场景 | 验证目标 | 自动化可证明 | 必须人工证明 |
|---|---|---|---|
| BSA-01 纯键盘 | 焦点顺序、标准多选、有限选择、清除与退出 | Button/ListView、SelectionMode、AutomationId 存在 | 焦点可见、顺序合理、无焦点陷阱 |
| BSA-02 Narrator | Name/角色/状态、单次最终数量播报 | Polite live region、事件抑制与最终事件调用存在 | 实际听读自然、无逐项重复、清除读为 0 |
| BSA-03 高对比度 | 焦点、选择、禁用及按下状态 | 主题资源与控件结构存在 | 各状态在真实对比度主题下可区分 |
| BSA-04 200% 文本缩放 | 文本、按钮、列表、状态区可达 | TextWrapping、响应式结构存在 | 无裁切/遮挡/强制水平滚动 |
| BSA-05 紧凑宽度 | 两组按钮纵排及宽窄往返 | 760 DIP 断点和 Grid 重排代码存在 | 可见/Tab/听读顺序一致且无布局震荡 |

详细固定动作、恢复步骤和脱敏模板见[运行手册](manual-testing/batch-selection-accessibility-runbook.md)。

## 4. 结果纪律与发布边界

每个场景只允许 `Pass`、`Fail` 或 `Inconclusive`，并单独保存首次结果、环境、`DesktopFilesChanged=False`、恢复确认和脱敏缺陷引用。重试成功不得覆盖首次失败；缺少听读、视觉、设置恢复或准备数据时必须记为 `Inconclusive`。

本阶段不宣称 Narrator、高对比度、文本缩放或纯键盘体验已经通过。五个 BSA 场景的真实记录、Issue #19/#20/#23/#24 外部矩阵、许可证、Publisher/证书和签名安装生命周期仍是发布阻断项。

## 5. 验证与后续方向

本地提交前门禁结果：

- 锁定依赖恢复、格式检查及 Release 构建通过，0 警告、0 错误；
- 544/544 测试通过；Stage 85 单份 Cobertura 行覆盖率 91.15%（8107/8894）、分支覆盖率 80.18%（2294/2861），通过 90%/75% 门槛；
- 启动链、134-ID UI、干净会话、单实例、Issue #19/#20/#23/#24 和新增 BSA 会话合同均通过；人工/硬件结果继续保持各自 Pending；
- DesktopHost 自动交互切片为 `Conditional Pass` 且 `DesktopFilesReadOrChanged=False`；配置持久化 20 个场景及 100 次保存、终止/ACL 注入通过；
- 文件操作安全与缩略图隔离探针均为 `ConditionalPass` 且清理成功；依赖漏洞门禁未发现已知漏洞；
- 首次把全部门禁置于单个高并行编排时，当前机器的并发构建负载令测试进程超过 20 分钟工具上限；仅清理命令行绑定 `stage85-tests.trx` 的自有进程树后，以单 MSBuild 节点复跑 45.8 秒通过。该环境编排超时未被记为产品 Pass，也未终止其他任务进程。

精确内部 RC、PR CI 与 main CI 将在本阶段准确提交上继续复核。

下一步应在无个人内容的 Windows 11 x64 专用账户逐项执行 BSA-01–BSA-05；若当前机器仍被外来 `LongGrid.App` 进程占用，则保持 Pending，不越权终止。专项结果关闭后，再与 Issue #19 的完整输入/系统表面矩阵合并判断正式工作区的无障碍准备度。
