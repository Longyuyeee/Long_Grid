# 统一最近配置编辑即时撤销审计

> 日期：2026-08-11
>
> 范围：正式 `LongGrid.App` 最近一次配置编辑的统一即时撤销入口
>
> 审计基线：`main` / `7b32823`（Stage 86 已合入）
>
> 结论：**统一交互入口已实现；既有强校验与保存边界不变；桌面文件和真实窗口继续零修改**

## 1. 需求与竞品交互对齐

交互审计要求布局、归属和合并等动作完成后立即提供 Undo；iTop/Fences 类产品的优势也在于用户不必返回动作发生的深层设置页寻找恢复入口。Stage 86 之前，Long方格已经为布局恢复、方格删除、批量引用加入、批量引用移除和批量引用改归属分别建立一次性撤销，但入口散落在三个产品卡片中。

本切片在正式工作区会话卡增加统一按钮，按当前令牌显示“撤销布局恢复 / 删除方格 / 批量加入 / 批量移除 / 批量改归属”。点击按钮本身即表示明确撤销意图，因此统一入口不再追加第二个确认对话框；它仍是标准 WinUI `Button`，继承 Tab、Enter 和 Space 操作。原有上下文撤销按钮暂时保留，避免在 BSA-01–BSA-05 尚未取得真实人工结果时同时改写既有焦点路径。

这不是无限撤销栈、Redo、标签页合并或活动历史。标签页仍属于后续 V1；本轮也没有把“容器合并”错误实现为删除源方格。

## 2. 唯一令牌与默认关闭

`ProductWorkspaceLatestUndoSelector` 同时检查五类协调器令牌。只有恰好一个令牌非空，且 `OperationId` 非空、对应 edit revision 为正数时，才返回可执行种类。以下状态全部默认关闭：

- 没有令牌：`Unavailable`；
- 两个或更多令牌同时出现：`Conflict`；
- 非空令牌的 operation ID 为空或 revision 非正数：`Conflict`。

协调器既有合同保证每个成功编辑或外部 revision 推进都会清空其他待撤销状态，成功撤销也会消费全部待撤销状态；统一选择器仍独立执行冲突防护，避免 UI 在内部不一致时猜测优先级。

## 3. 提交、安全与隐私边界

统一入口不复制 reducer、指纹或保存逻辑，只把原始令牌交回对应的五个 App commit delegate。Core/Infrastructure 随后继续验证 operation ID、当前 revision、配置前后 SHA-256 指纹、一次消费与唯一保存控制器接受结果。失败仍是有限状态，不执行其他种类的回退尝试。

UI 和 UIA 只暴露撤销种类、是否可执行以及固定的 `DesktopFilesChanged=False` / `DesktopWindowsChanged=False`。不暴露 operation ID、revision 数值、配置指纹、容器/项目 ID、路径、文件名、显示器身份或异常原文。本轮不读取文件内容，不移动、删除、重命名桌面文件，不创建、显示、隐藏或移动 DesktopHost 窗口。

## 4. UI、辅助功能与人工证据

新增 `ProductWorkspaceLatestUndoButton`，权威 UI 源码合同由 134 增至 135 个 AutomationId。按钮默认禁用且折叠；只有 selector 返回唯一可执行种类时才显示并更新可见文本、辅助功能名称和有限机器状态。会话卡不增加 Storyboard/Transition，保持 Reduced Motion 安全静态基线。

干净会话与 BSA 启动器同步要求 135-ID。`ValidateOnly` 不启动 GUI、不读取桌面元数据、不写配置、不修改系统设置或桌面文件，也不终止外来进程；其结果继续分别保持 `PendingCleanInteractiveSession` 和 `PendingManualEvidence`。135-ID、焦点顺序、Narrator 朗读、高对比、200% 文本缩放和紧凑布局仍需在专用干净账户复跑，源码合同不得冒充人工 Pass。

## 5. 自动证据与停止规则

定向测试覆盖无令牌、五类令牌准确映射、多令牌冲突、空 operation ID 和非正 revision 默认关闭。UI 源码合同锁定默认折叠/禁用、唯一事件处理器、五条原提交路径复用、冲突关闭、机器状态与 App 统一投影。Release 全解决方案构建已通过，0 警告、0 错误；单份 Stage 87 Cobertura 下 549/549 测试通过，行覆盖率 91.28%（16366/17930）、分支覆盖率 80.50%（4674/5806），通过 90%/75% 门槛。启动链、135-ID UI、干净会话、单实例、BSA 与 Issue #19/#20/#23/#24 安全入口均通过并保持各自 Pending；配置持久化 20 个场景、文件操作安全、DesktopHost 自动交互和依赖漏洞门禁通过既有结论。

缩略图隔离首轮退出码为 0 但内部 `Verdict=Fail`，恢复链没有成功；该结果未被退出码覆盖。独立复跑恢复为 `ConditionalPass`，明确 `ProductFallbackRequired=true`、ACL/Profile/临时沙箱清理成功且资源在暂定预算内。首轮 Fail 继续作为当前环境可重复性信号保留，不升级为产品 Pass，也不阻断本次未修改缩略图子系统的配置交互切片。准确提交 RC、PR/main CI 在发布阶段继续复核，未取得前不把本分支描述为主线完成。

若完整门禁发现既有协调器可同时发布多个有效令牌、统一入口绕开任一 Core 确认、上下文入口与统一入口产生双提交、UIA 泄露内部证据，或任何桌面文件/窗口发生修改，本切片必须停止发布并回退为不可用。

## 6. 后续方向

Stage 87 只改善已准入配置能力的可发现性，不改变 Phase 0 优先级。下一优先项仍是在专用环境执行 BSA-01–BSA-05、Issue #19、#20、#23、#24 的真实人工/硬件/专用卷矩阵；环境不可用时，只允许继续不扩张 Windows 权限面的正式工作区交互收口。标签页、任务栏美化、小组件/插件运行时、真实文件操作和 DesktopHost 产品执行继续按各自阶段准入。
