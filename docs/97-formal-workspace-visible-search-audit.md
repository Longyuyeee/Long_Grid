# Long方格正式工作区可见搜索审计（Stage 97）

## 1. 目标与需求对齐

桌面整理竞品普遍把“快速定位分组或项目”放在概览层。Long方格本阶段补齐正式工作区内的轻量搜索，但继续服从当前 Phase 0 的只读展示边界：提高定位效率，不把搜索扩展成磁盘扫描、索引服务、文件内容检索或真实桌面整理执行。

搜索与已有健康筛选组合使用，最终结果是二者的交集。这样既支持按方格、当前可见引用和有限健康标签定位，也保留“全部 / 待审查 / 空 / 正常”的可预测筛选语义。

## 2. 数据与隐私边界

允许进入搜索策略的字段只有：

- 方格的可见名称；
- `Empty / Ready / NeedsReview` 对应的有限展示标签；
- 当前 presentation 已展示的引用名称。

折叠方格的 `Items` 在 presentation 中为空，因此折叠后隐藏的引用不会命中搜索。这是有意的“所见即所搜”边界。路径、持久化身份、规范目标、详情文本、外观、机器状态、配置文档和 Catalog 条目均不得进入搜索输入。

查询最长 64 个字符；包含控制字符、超长输入或畸形展示数据时返回 `Invalid` 和零结果。机器状态仅记录 `Search=Empty/Applied/Invalid`，不得回显查询内容。

## 3. 交互合同

- 会话不可筛选时搜索框禁用并清空；可用后随输入即时更新 presentation 列表。
- 空白查询等同于无搜索，保留全部健康筛选候选。
- 非空查询只进行 `OrdinalIgnoreCase` 包含匹配，不做后台索引、模糊推断或网络调用。
- 结果继续复用现有 `ProductWorkspaceViewStatus` live region，只播报最终可见数量和“搜索已应用”，不播报查询文本。
- 显式“查看待审查引用”快捷入口会先清空搜索，再选择 `NeedsReview`，避免旧查询隐藏待审查方格。
- 新增唯一 `ProductWorkspaceSearchBox` AutomationId，权威 UI 合同由 137-ID 更新为 138-ID。

## 4. 权限与性能审计

该切片是同步、内存、presentation-only 操作，复杂度与当前展示方格及当前可见引用数量线性相关。它不触发 Catalog 刷新、配置保存、DesktopHost、Shell、桌面文件读取/写入/移动、任务栏或系统设置调用，也不新增常驻线程、缓存、索引文件或包依赖。

因此本阶段提升了 iTop Easy Desktop 类概览定位体验，同时不扩大安装容量、后台资源和高风险权限面。

## 5. 自动化证据与剩余人工项

自动化覆盖：

- 核心策略的方格名、健康标签、大小写不敏感引用名、空查询、无匹配、超长/控制字符和畸形输入；
- UI 源合同的 64 字符上限、禁用初态、事件接线、presentation-only 字段、查询不进入机器状态；
- 干净会话与 BSA 预检的 138-ID 权威计数。

仍需在专用账户人工验证键盘输入、Narrator 名称与播报、高对比度、200% 文本缩放、720px 紧凑宽度、中文输入法组合输入和触控。自动化通过不得替代这些证据，BSA 与 #19/#20/#23/#24 继续保持 Pending。

## 6. 阶段结论

Stage 97 通过条件是：策略与 App 编译、全量测试、覆盖率、UI/打包/文档/仓库门禁全部通过，并由 PR 与 main CI 复核。通过后，下一开发切片仍应优先选择不依赖许可证、签名证书或专用人工环境的配置/只读工作区交互收口；任务栏美化、小组件/Long助手插件、真实桌面文件整理和广泛窗口特效仍不进入当前授权范围。
