# Long方格正式方格健康状态审计

> 审计日期：2026-08-11
>
> 范围：正式工作区方格的空、正常、引用待审查有限状态与无障碍呈现
>
> 结论：配置只读状态切片；不读取文件内容、不修改桌面文件、不执行 DesktopHost，也不替代人工/硬件门禁

## 1. 需求与竞品交互对齐

最初 PRD 和交互审计要求容器的正常、空、加载、离线、错误与恢复状态必须在容器内部可理解，不能依赖弹窗风暴或颜色猜测。当前正式工作区已经能展示引用解析结果，但方格标题区仍只有计数；空方格、全部可用方格和含失效引用的方格缺少一眼可辨的状态标签。

本切片补齐当前数据链能够诚实判定的三种状态：

| 状态 | 判定 | 用户文本 |
|---|---|---|
| `Empty` | 方格没有引用 | 空方格 |
| `Ready` | 至少一个引用且全部解析成功 | 引用正常 |
| `NeedsReview` | 至少一个引用未解析 | 有引用待审查 |

它吸收竞品“分组标题直接显示健康摘要”的低干扰做法，同时遵守 Long方格的可信边界：`Missing`、`TypeChanged`、`Ambiguous` 和 `UnsupportedTarget` 统称“待审查”，不能在没有网络/文件系统实时证据时冒充“离线”或“错误”。Loading、真实离线、权限拒绝与运行时错误继续等待 Folder Portal/DesktopHost 的权威状态源。

## 2. 数据与隐私边界

`ProductWorkspaceReadModel` 在正式 v1 projector 校验后，由已匿名化的引用解析枚举和计数派生健康状态。快照增加空方格数与待审查方格数，App 只做有限中文映射；任何路径、持久化 target、profile/container/item ID、Catalog 来源、异常原文或显示器身份都不会进入状态。

状态优先级固定为：只要存在未解析引用即 `NeedsReview`；否则零引用为 `Empty`；其余为 `Ready`。未知枚举在展示层降级为“状态不可用”，不猜测成功。该状态是只读投影，不改变 schema、配置指纹、edit revision、撤销令牌或保存队列。

## 3. 视觉、交互与无障碍

- 每个方格标题右侧增加文字健康徽标，并保留外观摘要；颜色不是唯一状态表达。
- 方格 `AutomationProperties.Name` 同步朗读健康文本，`ItemStatus` 只包含序号、计数、布尔值与有限枚举。
- 工作区摘要和机器状态增加空方格数、待审查方格数，便于自动化确认有限状态。
- 不新增按钮、焦点站点、动画或 AutomationId，权威 UI 源码合同保持 135-ID。
- 折叠方格仍显示健康徽标，但继续不实例化引用行，保持现有性能与语义边界。

## 4. 安全和失败策略

本轮不读取文件内容，不探测网络状态，不移动、删除、重命名或打开桌面文件，不创建、移动、显示或隐藏 DesktopHost 窗口，也不增加后台轮询。投影前校验失败仍返回有限不可用状态且不产生部分快照；状态映射不触发保存。

若后续权威运行时来源出现，必须新增独立的 Loading/Offline/PermissionDenied/Error 状态机和超时/恢复规则，不能重解释本轮 `NeedsReview`。真实离线目录诊断仍属于后续 Folder Portal 与人工矩阵范围。

## 5. 自动证据与剩余门禁

定向测试覆盖混合解析方格、空方格、全解析方格、空工作区、隐私最小化与非法状态；UI 源码合同锁定三态派生、聚合计数、徽标绑定及 135-ID 不增长。Release 全解决方案构建为 0 warning / 0 error；单份 Stage 88 Cobertura 下 550/550 测试通过，行覆盖率 91.29%（16400/17964）、分支覆盖率 80.59%（4692/5822），高于 90%/75% 门槛。

启动、Issue #19/#20/#23/#24、BSA、135-ID UI、干净会话和单实例安全入口全部通过，并保持人工结论 Pending；配置持久化 20 场景、文件操作安全和依赖漏洞门禁通过。缩略图 worker 在当前机器继续得到诚实的 `ConditionalPass`：AppContainer 隔离、清理和资源预算通过，但 extraction/pixel-transfer/recovery 需要产品回退，不能升级为完整兼容结论。精确提交的 ZIP/MSIX/SBOM 聚合 RC 在提交后执行并记录到 PR。

Issue #19、#20、#23、#24 仍保持 OPEN；BSA-01–BSA-05、干净账户真实 UIA、Narrator、高对比度、200% 文本缩放、动态显示和专用卷证据仍为 Pending。源码合同通过不能替代这些人工结论。

## 6. 后续方向

在没有专用环境时，只继续不扩大 Windows 权限的正式工作区交互收口。下一优先级仍是执行 BSA 与 #19/#20/#23/#24 外部矩阵；获得权威 Folder Portal/DesktopHost 状态源后，再扩展 Loading/Offline/PermissionDenied/Error/Recovery。真实文件整理、任务栏美化、小组件/Long助手插件和广泛窗口特效不因本切片获得准入。
