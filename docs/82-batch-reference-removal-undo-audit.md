# 同方格批量引用移除与一次撤销审计

> 日期：2026-08-10
> 范围：同一正式方格内已解析引用多选、原子配置移除、整批一次撤销
> 安全边界：零桌面文件内容读取、写入、移动、删除或重命名

## 1. 需求与交互对齐

本切片延续有限批量配置语义。用户可在“已加入的引用”列表中使用 Windows 标准 Ctrl/Shift 多选；只有选择属于同一未锁定方格且数量为 1..256 时，批量移除按钮才开放并显示数量。执行前必须经过默认焦点为取消的确认框。

该列表仍服务引用改归属，因此改归属保持严格单选。跨方格混合选择不获得批量提交能力，避免把多个来源、多个目标和不同撤销边界混成一个含糊操作。

## 2. 原子状态转换与门禁

`ProductWorkspaceReducer.RemoveResolvedReferences` 在投影验证后的不可变快照上复核容器存在且未锁定、item ID 非空且唯一、所有 ID 均存在、所有目标均为已解析引用；随后一次性生成移除后的容器状态。任何条目无效时返回单一失败结果，不产生部分状态。

提交协调器复核 edit revision、容器 ordinal、1..256 数量、item ordinal 唯一、范围和解析状态。成功路径只调用一次 reducer、一次 projector、一次 `saves.Submit` 并推进一个 revision；失败路径不提交配置。

## 3. 整批一次撤销

批量移除复用已审计的引用移除撤销合同。令牌绑定操作 ID、移除后的 revision、移除后配置指纹和恢复配置指纹；撤销需显式确认并再次复核 revision、准确令牌和双指纹。任何其他成功编辑或外部 revision 推进都会使令牌失效，撤销成功后令牌立即消费。

## 4. UI、隐私和辅助功能

presentation 仅向 UI 提供方格 ordinal、项目 ordinal、可见名称和辅助功能名称，不暴露路径、持久化 target、ProfileId、SourceId、ContainerId、ItemId、ParsingName、VolumeId 或 FileId。机器状态记录批量数量、`Atomic=True`、revision、结果，并持续声明 `DesktopFilesChanged=False`。

本切片复用现有控件，因此 AutomationId 总数保持 130；源码合同新增 `SelectionMode=Multiple`、同方格限制、256 上限、原子 reducer/commit 和一次撤销断言。

## 5. 自动化证据

定向测试覆盖批量移除两个引用、保留未选择项、输入状态不变、整批一次撤销、第二次撤销拒绝、旧 revision、锁定方格、重复/越界 ordinal、超过 256 项和真实临时文件内容前后相同。全量 Release 测试为 544/544 通过；单份 Cobertura 为行 91.15%（8107/8894）、分支 80.18%（2294/2861），通过 90%/75% 门槛。Release 构建为 0 警告、0 错误；130-ID 源码合同与干净会话 `ValidateOnly` 已通过。内部 RC 与 PR/main 双 CI 仍须在准确提交上复核。

## 6. 下一步

配置层的批量加入与同方格批量移除已形成对称闭环。下一步应优先审计“批量选择状态下的共同操作栏与键盘可达性”，或转入经独立授权的可见 DesktopHost 产品接线；跨方格批量改归属、真实桌面文件操作、任务栏美化、小组件和插件运行时仍不由本切片授权。
