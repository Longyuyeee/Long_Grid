# Long方格正式工作区零结果恢复审计（Stage 99）

## 1. 目标与交互对齐

现有交互规范要求空状态必须暴露主动作，不能只显示空白矩形。Stage 97–98 已允许搜索、健康筛选和有限排序组合，但组合条件得到零结果时，正式工作区只剩状态文字，缺少明显的恢复路径。

本阶段新增零结果恢复卡片和“重置工作区视图”主动作。它只在原工作区确实存在方格、当前结果为零、会话允许筛选且至少一个视图条件不是默认值时出现。

## 2. 准入与失败边界

`ProductWorkspaceViewResetPolicy` 只消费：会话是否可筛选、总方格数、可见方格数、有限健康筛选、是否存在搜索查询和有限排序模式。它不接收查询内容、方格名称、路径、身份、配置、Catalog 或桌面事实。

以下情况不显示恢复入口：

- 会话不可筛选；
- 正式配置本来就没有方格；
- 当前仍有可见方格；
- 搜索、筛选和排序都处于默认状态；
- 计数为负数或可见数大于总数。

未知筛选或排序若已造成零结果，可通过重置动作恢复到有限默认值；这不是把未知状态降级为成功，而是显式撤销当前视图条件。

## 3. 重置事务与焦点合同

用户显式点击后，App 在本地 UI 事务中：

1. 抑制搜索、筛选和排序三个控件的中间变化事件；
2. 清空搜索；
3. 恢复“全部方格”；
4. 恢复“配置顺序”；
5. 将焦点移回搜索框；
6. 仅应用一次最终 presentation 并更新一次 live-region 状态。

入口在状态变化后失效时拒绝执行，并播报有限拒绝状态。机器状态只记录可用性、是否聚焦和 `Changed=False / DesktopFilesChanged=False`，不记录查询文本。

## 4. 权限、性能与容量审计

恢复动作只改当前窗口控件值，不持久化用户选择，不提交配置，不重新枚举 Catalog，不创建方格，也不读取、写入或移动桌面文件。它不调用 DesktopHost、Shell、任务栏、系统设置、网络、遥测或后台线程。

该切片新增一个标准 Button 和一个轻量空状态 Border，不新增包依赖、缓存、索引文件或资源资产。权威 UI 合同由 139-ID 更新为 140-ID。

## 5. 自动化证据与人工缺口

核心测试覆盖健康筛选、搜索、排序、未知条件的可恢复零结果，以及会话不可用、原始空工作区、已有结果、默认视图和非法计数。UI 源合同覆盖默认折叠/禁用、显式点击、批量事件抑制、三控件默认值、焦点恢复、单次最终应用、无提交/保存/DesktopHost 路径和 140-ID。

真实键盘、Narrator、高对比度、200% 文本缩放、720px 紧凑宽度、触控和焦点感知仍需专用账户人工验证。BSA 与 #19/#20/#23/#24 继续保持 Pending。

## 6. 阶段结论

Stage 99 完成的是可恢复的浏览空状态，不是真实配置或桌面内容恢复。通过本地门禁、PR CI 与 main CI 后才可收口；任务栏美化、小组件/Long助手插件、真实文件整理和广泛窗口特效仍不进入当前 Phase 0 权限范围。
