# Long方格正式工作区有限排序审计（Stage 98）

## 1. 目标与竞品对齐

桌面整理与 Folder Portal 类竞品通常允许用户按名称或状态调整分组浏览顺序。Long方格本阶段在正式工作区补齐有限排序，并与健康筛选、可见搜索组合：先按搜索和健康状态确定候选，再只对候选 presentation 排序。

本阶段提供四种有限模式：

- 配置顺序：默认值，保持正式配置投影出的展示顺序；
- 名称升序：使用大小写不敏感的确定性比较；
- 名称降序：使用相同比较规则反向排列；
- 待审查优先：仅把 `NeedsReview` 方格前置，各组内部保持原顺序。

当前没有可信的最近使用事实源，因此不提供“最近使用”排序，也不通过点击次数、焦点或搜索行为推断活跃度。

## 2. 稳定性与失败边界

名称相同（忽略大小写）时以进入策略的展示索引作为稳定次序；待审查优先同样以原索引保持组内稳定。未知排序模式、空名称或未知健康枚举统一返回 `Invalid` 和零结果，不猜测回退到配置顺序。

排序输入白名单只有可见方格名称和有限健康枚举。路径、引用名称、详情、外观、机器状态、配置身份、Catalog、使用时间和遥测均不进入策略。

## 3. 交互与可访问性合同

- 排序器是标准 ComboBox，默认“配置顺序”，会话不可筛选时禁用；
- 四种模式具备固定源码顺序与有限索引映射，未知索引失败关闭；
- 切换后复用现有工作区 live region，一次播报排序名称与最终可见数量；
- 排序不会改变方格 `Ordinal`，卡片管理、快速折叠与快速锁定仍按唯一序号对齐，不依赖可见列表位置；
- 新增唯一 `ProductWorkspaceSortSelector`，权威 UI 合同由 138-ID 更新为 139-ID。

## 4. 性能、容量与权限审计

排序仅在用户切换模式、搜索变化、筛选变化或正式 presentation 刷新时，对当前候选执行内存排序。复杂度上限为 `O(n log n)`，不新增缓存、索引文件、依赖、线程、定时器或持久化字段。

该切片不触发 Catalog 刷新、配置保存、桌面文件读取/写入/移动、DesktopHost、任务栏、系统设置或网络调用，符合轻量、稳定和权限最小化方向。

## 5. 自动化证据与人工缺口

自动化覆盖配置顺序、名称升降序、大小写不敏感稳定并列、待审查优先稳定分组、未知模式、畸形输入和空输入集合；UI 源合同覆盖默认值、四选项、禁用初态、事件接线、presentation-only 输入和 139-ID 计数。

真实键盘、Narrator、高对比度、200% 文本缩放、720px 紧凑宽度、触控与排序后焦点感知仍需专用账户人工验证。BSA 与 #19/#20/#23/#24 继续保持 Pending。

## 6. 阶段结论

Stage 98 只补齐正式工作区浏览效率，不改变配置或真实桌面顺序。通过完整本地门禁、PR CI 和 main CI 后才可收口；任务栏美化、小组件/Long助手插件、真实文件整理和广泛窗口特效仍不进入当前 Phase 0 权限范围。
