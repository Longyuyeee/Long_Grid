# Long方格正式待审查引用快捷入口审计

> 审计日期：2026-08-11
>
> 范围：正式方格健康筛选到既有匿名未解析引用审查选择器的显式跳转
>
> 结论：只读展示与焦点切片；不执行审查决定、不保存配置、不修改桌面文件、不执行 DesktopHost

## 1. 需求与交互对齐

Stage 88–89 已完成“状态可理解 → 状态可筛选”，但用户筛出待审查方格后仍需自行寻找既有匿名审查入口。交互审计要求概览中的待处理状态提供就近且可预测的快速入口；本切片因此在健康筛选旁增加“查看待审查引用”按钮，形成“识别状态 → 聚焦待处理范围 → 进入匿名审查控件”的最小闭环。

按钮不是新的审查工作流。点击只把正式方格筛选切换为 `NeedsReview`，并以 `FocusState.Programmatic` 聚焦既有 `ProductWorkspaceReferenceReviewSelector`；不会自动选择保留、重选或移除，不会代替用户确认，也不会把未解析引用解释成网络离线、权限拒绝或文件系统错误。

## 2. 准入与失败关闭

`ProductWorkspaceReviewShortcutPolicy` 只在以下条件同时成立时开放快捷入口：正式工作区未解析引用数大于零、匿名审查快照项数与该总数完全相等、审查快照可用且无错误。工作区 read model 每次刷新时，按钮先禁用并折叠为 `PendingAlignment`；只有同一同步刷新链随后应用了对齐的审查 presentation 才重新开放。

零项、数量不等、审查不可用、错误或尚未对齐均默认关闭。按钮的可见性与可用性由同一策略计算，避免展示可点击但无法完成的入口，也避免把上一会话的审查快照错误关联到新工作区。

## 3. 无障碍、隐私与响应式

- 按钮是标准 WinUI `Button`，可通过 Tab 到达；只有用户明确点击后才移动焦点，不在会话加载或状态变化时抢占焦点。
- 自动化名称只表达匿名待审查数量，不包含文件名、路径、方格名称、稳定 ID 或异常原文。
- `ItemStatus` 使用有限机器状态、计数、焦点结果和 `DesktopFilesChanged=False`；焦点调用失败时不会虚报成功。
- 新增 1 个 AutomationId，权威源码合同从 136 增至 137；不增加动画、后台任务或自定义键盘实现。
- 筛选器与按钮使用同一双列布局，仍受现有紧凑断点约束；Narrator、高对比、200% 文本缩放与真实紧凑窗口结果继续保持 Pending，不能由源码合同代替。

## 4. 安全边界与非目标

本切片不刷新 Catalog，不读取文件内容，不取得路径或 workspace identity，不写配置、不递增 revision、不创建撤销令牌，也不移动、删除、重命名或打开桌面文件。它不调用 DesktopHost、不修改系统设置，不增加任务栏美化、小组件/插件运行时或广泛窗口特效能力。

入口只帮助定位既有匿名审查 UI；真正的保留、重选或移除仍走原有显式按钮、确认和唯一保存控制器。真实 Loading/Offline/PermissionDenied/Error/Recovery 仍需后续权威运行时状态源。

## 5. 自动证据与外部门禁

Core 定向测试覆盖 1..256 对齐成功，以及零项、数量不等、审查不可用和负数输入的失败关闭。源码合同锁定默认折叠/禁用、刷新时等待对齐、精确计数策略、显式点击切换 `NeedsReview`、以程序化焦点进入既有匿名选择器、有限 UIA 状态和 137-ID 完整性。

Release 全解决方案构建为 0 warning / 0 error；单份 Stage 90 Cobertura 下 558/558 测试通过，行覆盖率 91.33%（16440/18000）、分支覆盖率 80.66%（4714/5844），高于 90%/75% 门槛。启动、Issue #19/#20/#23/#24、BSA、137-ID UI、干净会话和单实例安全入口通过，并诚实保持人工结论 Pending；配置持久化 20 场景和依赖漏洞门禁通过。文件操作安全探针保持 `ConditionalPass`，真实 Explorer 撤销、跨卷、ACL、云占位符等仍需受控测试；缩略图 worker 也保持 `ConditionalPass`，隔离、清理和资源预算通过，但当前 AppContainer 提取、像素传输与故障恢复仍要求产品回退。精确提交 RC 在提交后执行并记录到 PR。任何自动门禁通过都不替代真实 Narrator、高对比、200% 文本缩放、紧凑布局和干净账户 live UIA。

Issue #19、#20、#23、#24 继续保持 OPEN；BSA-01–BSA-05、动态显示、五人无提示测试与专用卷证据仍为 Pending。

## 6. 后续方向

若专用环境可用，下一步优先执行外部人工、硬件与专用卷矩阵；若仍不可用，只继续有限只读展示交互收口。真实文件整理、任务栏美化、小组件与 Long助手插件兼容仍按既定后续阶段准入，不因本快捷入口提前开放。
