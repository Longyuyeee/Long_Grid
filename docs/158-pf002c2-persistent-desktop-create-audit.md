## 1. 审计发现与目标

PF-002C1 已让空工作区的按钮、右键菜单、`Ctrl+Alt+N` 和 UIA Invoke 进入同一安全请求，但首个方格提交后，空态投影消失，创建入口和快捷键也随之消失。用户创建第二个方格仍必须返回控制中心。这与 iTop Easy Desktop、Stardock Fences 的“桌面是持续创建主场”存在直接功能差距。

本轮关闭这个工程缺口：只要 DesktopHost 处于安全的 Passive 状态，已有方格旁仍显示一个产品自有“+ 新建方格”入口；点击、在入口上右键、`Ctrl+Alt+N` 或 UIA Invoke 继续复用 Stage 157 的同一请求、双重 admission、Stage 156 默认值和唯一配置提交协调器。

## 2. 产品行为

### 2.1 持续入口

- 工作区为空时继续显示原“创建第一个方格”卡片；
- 工作区非空时，每个权威显示器建立 DesktopHost Surface，并在存在安全空位时显示 144×40 DIP 的“+ 新建方格”入口；
- 点击或在该入口上打开右键菜单，创建目标绑定当前入口所属显示器；
- 所有显示器都可提供就近鼠标/UIA入口，包括当前没有方格的权威显示器；
- `Ctrl+Alt+N` 只由权威主显示器 Surface 注册，避免多 Surface 抢占同一系统快捷键；
- 快捷键目标固定为主显示器，鼠标/右键/UIA目标为操作所在显示器。

### 2.2 空位与穿透

持续入口按 DPI 换算尺寸、边距和间隔，从右上开始以有限网格扫描第一个不与现有方格相交的位置。扫描只使用投影内匿名几何，不读取桌面文件、图标或内容。

- 找到空位：将入口区域并入窗口 region，该小区域可命中；
- 没有空位：该显示器不绘制、不命中也不向 UIA 暴露入口；原方格不被覆盖；
- 方格区域和入口以外区域在 Passive 下继续返回 `HTTRANSPARENT`；
- 每次权威投影 revision 更新都会重新计算位置，旧 Surface 被释放，旧请求由 revision admission 拒绝。

### 2.3 与选择模式互斥

项目选择需要 Explicit Surface，本轮明确不让创建入口与选择竞争：

- 进入 Explicit 时注销 `Ctrl+Alt+N`；
- 持续创建按钮不绘制、不加入窗口 region、不出现在 UIA 导航中；
- UIA create provider 报告 disabled/offscreen，Invoke 不提交请求；
- 返回 Passive 后重新计算 region、重绘入口并仅在主显示器恢复快捷键；
- Hidden、禁用和 Dispose 继续注销快捷键并清空窗口 region。

## 3. 投影模型纠偏

原非空投影只为“已有方格的显示器”创建 Surface，因此无法在尚无方格的副屏直接创建。本轮给显示器投影增加两个权威事实：

- `IsPrimary`：保证一个批次恰有一个主显示器，决定唯一快捷键所有者；
- `WorkspaceIsEmpty`：区分“整个工作区为空”和“该显示器当前零方格”。

非空工作区现在保留全部权威显示器；空工作区仍只在主显示器显示大型首建卡片。批次拒绝零个/多个主显示器以及混合的 workspace-empty 标志，避免不同 Surface 对同一工作区状态产生冲突解释。

## 5. 失败与边界矩阵

| 状态/事件 | 结果 | 副作用 |
| --- | --- | --- |
| 非空权威工作区进入 Passive | 计算安全空位并显示入口 | 零配置写入 |
| 权威显示器当前零方格 | 仍建立有限 Surface 和入口 | 可在该显示器创建 |
| 入口候选与任一方格相交 | 扫描下一有限候选 | 不覆盖方格 |
| 所有候选被占用 | 返回 null，隐藏该屏鼠标/UIA入口 | 方格和选择保持不变 |
| 多显示器均尝试注册快捷键 | 仅 `IsPrimary=true` Surface 注册 | 最多一个注册 |
| 快捷键冲突 | 注册失败，鼠标/右键/UIA继续可用 | DesktopHost 不失败 |
| 进入 Explicit | 隐藏入口并注销快捷键 | 选择流程独占输入 |
| 返回 Passive | 重建 region、重绘并尝试恢复快捷键 | 不抢前台 |
| Surface Hidden/Dispose | 注销快捷键、清空/销毁窗口 | 零注册残留 |
| revision/topology 在排队期间变化 | App 二次 admission 拒绝 | 零创建、零保存 |
| 显示器失去权威性/消失 | App 拒绝目标显示器 | 零创建、零保存 |
| lifecycle 不是 AwaitingWorkspace/ReadyReadOnly | App 拒绝 | 零创建、零保存 |
| 容量、名称或提交失败 | 统一协调器返回拒绝 | 显示有限失败，不移动文件 |

## 6. 验收证据

新增或强化的合同包括：

- 持续按钮选择第一个不与方格相交的有限槽位；全部占满时返回 null；
- 非空投影保留没有方格的权威显示器，并精确标记唯一主显示器；
- 非空原生 Surface 暴露标准 UIA Button/Invoke 和持续键盘请求；
- Explicit 切换注销快捷键并拒绝持续创建请求；
- App 在 `AwaitingWorkspace` 与 `ReadyReadOnly` 两种安全状态接受当前请求，其他状态拒绝；
- 20 个连续权威 revision 每次只由最新 Surface 产生当前 revision 请求，19 个旧 Surface 全部释放，最终 Dispose 后零存活 Surface；
- 源码合同锁定空态与持续入口、ReadyReadOnly 门禁、真实菜单和统一提交路径。

本地最终结果：

- PF-002C2 投影/布局/lifecycle/native/UIA 聚焦测试：`67/67`；
- 20 次最新请求生命周期合同：通过；
- 全量测试：`972/972`；
- Release 解决方案构建：`0 warning / 0 error`；
- `dotnet format --verify-no-changes`：通过；
- UI 源码合同：`146 AutomationId`，`outcome=Pass`；
- `git diff --check`：通过。

20 次生命周期合同证明持续入口随权威 revision 更新、陈旧 Surface 释放和请求盖章正确；它不是 20 次物理点击、焦点或视觉呈现证据。物理鼠标、键盘、触控、Narrator、高对比和多 DPI 仍保留给 PF-002F。

## 8. 严格下一步

1. **PF-002D：提交前就地预览与命名**。按钮、右键、键盘和 UIA 不再立即提交，而是统一打开有限预览；显示默认名称、显示器、位置和尺寸，允许提交前编辑名称。
2. 预览必须绑定 workspace revision、topology generation 和目标显示器；Esc、失焦、Explicit/Hidden、安全门关闭、显示器变化或新请求替换均取消且零残留。
3. **PF-002E：保存与窗口发布补偿事务**。保存成功后确认可见发布，失败撤回投影/窗口并提供有限重试，禁止幽灵方格。
4. **PF-002F：正式证据收口**。执行物理输入、连续 20 次、焦点、触控、Narrator、高对比、文本缩放和 100%～400% DPI 矩阵。
5. 随后补桌面绘制矩形和“使用 Long方格已选引用创建”，再决定 PF-002 是否可以升级完成并进入 PF-003。
