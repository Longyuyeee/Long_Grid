# Stage 101：正式方格名称即时引导审计

日期：2026-08-12

范围：正式方格创建/重命名的提交前反馈、按钮准入、辅助技术与权限边界

结论：自动化范围通过；真实键盘、Narrator、缩放、触控和焦点证据仍为 Pending

## 1. 需求对齐

Stage 100 已让空工作区用户快速到达名称输入框，但此前表单只在空白时禁用按钮。所选方格已锁定、名称 trim 后没有变化或当前会话只读时，界面没有提交前解释；其中锁定方格甚至仍可点击重命名，再由 reducer 事后拒绝。这增加了首次创建和日常管理的试错，与“首次创建容器中位数 < 2 分钟”、现代表单即时反馈以及操作前解释结果的交互要求不一致。

本阶段新增有限名称意图策略和输入框下方的即时提示，继续保留“创建并保存”和“重命名并保存”两个明确动作，不引入自动提交。

## 2. 策略与交互

`ProductWorkspaceContainerNameIntentPolicy` 只消费：

- 当前输入名称；
- 编辑器是否允许创建和重命名；
- 当前选中方格的可见名称；
- 当前选中方格是否锁定。

策略复用 `ProductConfigurationLimits.MaximumNameLength`，对输入 trim 后判空，返回有限状态以及独立的 `CanCreate`/`CanRename`。锁定选择、没有重命名权限或 trim 后与当前名称完全相同均关闭重命名；合法名称仍可按现有产品语义用于显式创建。

可见提示覆盖非法、只读、空名称、可创建、锁定、无变化和可重命名等状态。相同提示同步到名称 TextBox 的 HelpText，辅助技术可以在控件上下文读取；提示 TextBlock 不设置 `LiveSetting`，避免 `TextChanged` 的每个按键都触发重复播报。

## 3. 安全与权限边界

该策略不读取路径、Catalog、持久化目标、文件内容、稳定身份或遥测，也不调用保存、配置提交、DesktopHost 或桌面文件操作。它只决定两个现有按钮是否启用并生成有限提示。真正创建或重命名仍通过既有显式点击、共享 edit revision、reducer、配置校验和唯一保存控制器完成。

重复名称仍沿用现有正式配置语义；本阶段没有在 presentation 层发明新的唯一性约束。大小写变化仍视为真实重命名，比较采用 `StringComparison.Ordinal`，与配置的精确字符串变化保持一致。

## 4. 自动化证据

- Core 单元测试：633/633；
- 覆盖率：行 91.21%、分支 81.43%，通过 90%/75% 门禁；
- UI 源码合同：142-ID，通过；
- 覆盖 null、超过 256 字符、只读、空白、仅创建、可重命名、trim 后无变化、锁定和无重命名权限；
- 源码合同确认按钮只消费策略结果、提示写入 HelpText、提示不是 live region；
- 源码合同确认策略没有 Catalog、保存、遥测、文件或 DesktopHost 权限。

完整 Release/RC 门禁在本阶段发布前重新生成并记录。真实键盘焦点顺序、Narrator 按需读取、200% 文本缩放、720px 紧凑布局、高对比度和触控仍必须在专用账户人工验证。
