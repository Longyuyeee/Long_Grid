# 正式产品配置存储适配器审计

审计日期：2026-08-04

结论：**Production adapter slice pass / App lifecycle and real-volume evidence pending / Issue #24 保持 OPEN**

## 1. 本轮目标

把 P0-06 Spike 已验证的核心存储语义迁移到正式产品边界，并直接使用 `LongGrid.Core.Configuration` v1 schema。本轮只建立可被后续 App 注入的 Infrastructure 适配器，不接 WinUI 生命周期，不执行危险的真实卷耗尽/只读操作，也不以自动测试替代专用环境证据。

## 2. 需求追踪

| 需求 | 正式实现 | 自动证据 | 状态 |
|---|---|---|---|
| 版本化产品 schema | `ProductConfigurationJson` v1 | 写前序列化与暂存后复读均使用同一合同 | Pass |
| 原子发布 | 同目录 `.new` → flush → 复读 → `File.Move`/`File.Replace` | 首次保存与替换测试 | Pass（应用级） |
| 上一版备份 | 替换时将旧主文件写入 `.bak` | 主/备内容分别复读 | Pass |
| 损坏恢复 | 主文件无效时只读取有效备份 | 损坏主文件测试 | Pass |
| 安全模式 | 主备均不可用时返回有限状态 | 空主文件、缺失备份、超大文件与 I/O 测试 | Pass |
| 证据保护 | Recovery/SafeMode 状态拒绝普通保存 | 损坏字节保持不变 | Pass |
| 跨进程单写 | 持久 `.lock` 文件、`FileShare.None`、有界重试 | 超时、释放后恢复、调用方取消 | Pass |
| 有限错误 | 公共结果/异常只暴露枚举，不携带路径或 JSON | 无路径泄露断言 | Pass |

## 3. 边界与安全判定

- “原子”仅指同一文件系统目录中的应用级发布边界；不承诺所有磁盘、文件系统或断电场景具有相同耐久性。
- 主文件损坏但备份有效时只返回 `RecoveredFromBackup`，不会自动覆盖或删除原始损坏证据。
- 主备均不可用时返回 `SafeMode`；恢复 UI 尚未接入，因此当前不能描述为用户可完成的恢复流程。
- 写租约只串行化配置提交，不等同于完整应用单实例。应用激活转发、进程所有权与第二实例退出仍是独立切片。
- 本轮没有修改真实卷、ACL、系统设置、任务栏或 Explorer。

## 4. 自动验证

- `dotnet format LongGrid.sln --verify-no-changes --no-restore`；
- Release solution build，零警告、零错误；
- 131/131 自动测试通过，其中正式存储与协调器测试共 20 个；
- 聚合覆盖率：行 91.92%，分支 79.93%，高于 90%/75% 门禁；
- P0-06 独立探针继续作为强杀、故障注入和权限矩阵证据，不被产品程序集引用。

## 5. 未完成项

1. 完成单实例激活和第二实例参数转发；
2. 提供安全模式/备份恢复 UI，并确保用户确认后才覆盖损坏证据；
3. 将经过批准的真实产品状态显式接入保存队列；当前只读 Shell 保持零入队；
4. 在专用可恢复卷执行 I24-01 容量/配额耗尽与 I24-02 只读卷；
5. 验证真实断电、非 NTFS、企业重定向目录与长期并发压力。

上述项目完成前，Issue #24 必须保持打开；本轮不得把 `Conditional Pass` 升级为完整生产发布结论。
