## 6. 固定收尾顺序与验收目标

### 第一步：关闭 G0-01 环境门禁

负责人提供无个人内容的专用 Windows 11 x64 账户或可抛弃 VM；用户/Public Desktop 均为空，AC/DC 睡眠均为 0，待重启信号清除，准备仓库外空证据目录。验收只看 live 预检输出 `ReadyForM4c2cSession`。

不得在当前个人账户删除桌面内容，不得由脚本修改电源/更新策略，不得降低失败码条件。

### 第二步：执行和裁决真实 24 小时会话

在同一干净 commit 上运行完整 24 小时，60 秒采样，预期 1441 个样本，覆盖率至少 98%，最大间隔不超过 180 秒；App/worker 不退出、不重启，资源趋势、状态修订和 worker/Profile 终态满足 Stage 150 固定预算。原始证据先保持 Pending，再由独立复审器输出 `EligibleForM4cDecision`，最后由人工审计裁决 M4c。

### 第三步：按 G0-02～G0-07 汇合外部证据

1. G0-02 / Issue #23：完成 P1～P5 五人无提示首次整理；
2. G0-03 / Issue #19：完成物理输入、Narrator、无障碍与系统表面；
3. G0-04 / Issue #20：完成八项动态显示/会话矩阵；
4. G0-05 / Issue #24：完成专用卷容量/只读失败恢复；
5. G0-06：裁决 ADR-0001/0002、四个 Issue 与 Phase 0 出口；
6. G0-07：批准许可证和证书，完成签名安装生命周期。

每一编号仍须独立分支、专项审计、目标测试、PR CI、合并后 main CI 和要求的真人/实机证据。只有 G0 全部通过或负责人逐项书面 Accepted Risk，才允许从稳定 RC 基线进入 CP1-01。

## 7. 当前允许与禁止的工作

**允许**：准备合规环境、执行既有只读预检、采集/复审真实证据、修复实测发现的阻断缺陷、维护运行手册和必要的等价维护。
