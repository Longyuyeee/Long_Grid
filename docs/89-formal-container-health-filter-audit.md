# Long方格正式方格健康筛选审计

> 审计日期：2026-08-11
>
> 范围：正式工作区全部/待审查/空/正常方格的内存态筛选、键盘与 UIA 反馈
>
> 结论：展示层交互切片；不刷新 Catalog、不保存配置、不修改桌面文件、不执行 DesktopHost

## 1. 需求与竞品对齐

Stage 88 已让每个正式方格显示“空方格 / 引用正常 / 有引用待审查”，但用户仍需逐个浏览才能找到需要处理的分组。交互审计要求概览提供待处理项和快速入口，并用任务 7 验证用户能找出内容未显示的异常目录；iTop/Fences 类产品的优秀点也在于分组状态可快速聚焦，而不是只展示被动徽标。

本切片增加一个标准 WinUI `ComboBox`，提供四个互斥模式：

| 模式 | 呈现范围 |
|---|---|
| 全部方格 | 不按健康状态隐藏 |
| 待审查方格 | 只显示 `NeedsReview` |
| 空方格 | 只显示 `Empty` |
| 引用正常方格 | 只显示 `Ready` |

它完成“状态可见 → 状态可聚焦”的最小闭环。筛选只表示正式引用解析健康度；`NeedsReview` 不等于网络离线、权限拒绝或文件系统错误，真实原因仍由既有匿名引用审查入口解释。

## 2. 数据、状态和失败边界

筛选输入只消费 `ProductWorkspaceReadPresentation` 中的隐私最小化容器和有限 `HealthKind`。它不取得 workspace state、CatalogEntry、持久化 target、路径、内部 ID、显示器身份或异常原文。完整 presentation 保存在窗口内存中，session 重建后按当前选项重新投影；无正式会话时筛选器禁用。

`Invalid / All / NeedsReview / Empty / Ready` 是封闭枚举。索引缺失、未知枚举或畸形状态统一返回零项 `WorkspaceViewFilterUnavailable`，禁止把未知模式降级为“显示全部”。筛选不更改全量计数、配置 schema、edit revision、保存队列或撤销令牌。

## 3. 交互、无障碍与响应式

- 筛选器默认选择“全部方格”，正式会话可筛选时才启用；使用标准 ComboBox 键盘与屏幕阅读器模式。
- 每次选择只更新一次现有 `ProductWorkspaceViewStatus` live region，播报筛选名称及“可见数/总数”。
- UIA `ItemStatus` 只包含有限筛选枚举、容器计数和 `DesktopFilesChanged=False`，不包含可见名称或路径。
- 零匹配不是错误，明确播报 `0/总数`；未知模式才进入不可用状态。
- 新增 1 个 AutomationId，权威源码合同从 135 增至 136；不增加动画、后台任务或自定义焦点实现。
- 标准 ComboBox 与列表继续参与现有 760 effective-pixel 紧凑布局；200% 文本缩放、高对比和 Narrator 真实结果仍需专用账户复核。

## 4. 安全与非目标

本轮不读取文件内容，不重新枚举桌面，不刷新 Catalog，不写 Long方格配置，不移动、删除、重命名或打开桌面文件，不修改系统设置，也不创建、移动、显示或隐藏 DesktopHost 窗口。筛选器不是全局搜索、Folder Portal 离线诊断或活动中心，也不扩大任务栏、小组件/插件和窗口特效范围。

## 5. 自动证据与外部门禁

Core 定向测试覆盖全部/待审查/空/正常四种模式、`Invalid` 和未知枚举默认关闭；源码合同锁定默认禁用/全量选择、四个有限选项、唯一 SelectionChanged handler、presentation-only 数据边界、未知模式零结果、单一 live region 和 136-ID。首轮定向构建发现 switch 元组中的 `null` 缺少显式可空类型，未产生提交；改为 Core 有类型策略后复跑通过。

Release 全解决方案构建为 0 warning / 0 error；单份 Stage 89 Cobertura 下 551/551 测试通过，行覆盖率 91.31%（16430/17994）、分支覆盖率 80.57%（4702/5836），高于 90%/75% 门槛。启动、Issue #19/#20/#23/#24、BSA、136-ID UI、干净会话和单实例安全入口通过并保持人工结论 Pending；配置持久化 20 场景、文件操作安全和依赖漏洞门禁通过。缩略图 worker 继续诚实保持 `ConditionalPass`：隔离、清理和资源预算通过，提取/像素传输/恢复仍要求产品回退。精确提交 RC 在提交后执行并记录到 PR。

Issue #19、#20、#23、#24 继续保持 OPEN；干净账户 live UIA、BSA-01–BSA-05、Narrator、高对比、200% 文本缩放、动态显示与专用卷仍为 Pending。136-ID 源码合同不得冒充人工通过。

## 6. 后续方向

优先执行外部人工/硬件/专用环境矩阵。若环境仍不可用，只继续有限展示交互收口；下一步可评估把待审查筛选与既有匿名审查选择器建立明确焦点跳转，但不得用展示筛选替代真实离线/权限诊断。真实文件整理、任务栏美化和小组件/Long助手插件继续按既定后续阶段准入。
