# Long方格布局恢复一次性配置撤销审计

> 审计日期：2026-08-06
>
> 范围：恢复前快照、一次性撤销令牌、共享 revision/save 门禁、WinUI 明示撤销
>
> 结论：配置级恢复已具备同会话一次性撤销；真实窗口与桌面文件操作继续断开

## 1. 需求对齐与安全边界

本阶段承接配置级布局恢复确认，为一次成功恢复保留恢复前的工作区状态，并签发一次性撤销令牌。撤销只把 Long方格配置恢复到该次恢复之前，经正式 v2 projector 复核后进入既有 `ProductWorkspaceSaveController`。它不调用 `LayoutRecoveryTransactionCoordinator`、`ILayoutRecoveryWindowBatchAdapter`、Explorer 或文件操作接口，也不读取、移动、隐藏或创建真实窗口。

令牌只在恢复提交被保存控制器接受后产生；恢复预览、取消、门禁拒绝和保存拒绝均不产生撤销。备份只读会话不展示撤销入口。

## 2. 一次性令牌与复核

令牌绑定以下有限证据：

- 随机恢复操作 ID；
- 恢复提交后的共享 edit revision；
- 恢复后完整配置 SHA-256 指纹；
- 恢复前完整配置 SHA-256 指纹；
- 恢复前容器计数。

确认撤销时，协调器必须仍持有同一恢复前状态和同一令牌；Core 重新投影当前状态与恢复状态并重算两个指纹。revision 变化返回 `EditRevisionChanged`，令牌或恢复快照不一致返回 `TokenMismatch`，当前配置在相同 revision 下变化返回 `CurrentConfigurationChanged`。取消返回 `ConfirmationRequired`，不会保存、递增 revision 或消费令牌。

## 3. 生命周期与并发规则

撤销状态与引用、容器、恢复提交共享同一把锁、同一 edit revision 和同一保存控制器：

- 成功恢复：revision 加一并替换为该次恢复的撤销状态；
- 其他引用/容器编辑成功或外部 revision 推进：立即清除旧撤销；
- 撤销保存被控制器拒绝：保留令牌与恢复前状态，revision 不变；
- 撤销保存被接受：revision 加一并立即清除令牌；重复使用返回 `Unavailable`；
- App 重启：内存中的一次性撤销自然失效，不把敏感恢复快照另行持久化。

该策略防止用户在后续编辑后用旧快照覆盖新配置，也避免新增第二条存储路径。保存控制器的原子落盘、失败重试和关闭排空规则保持不变。

## 4. 交互与隐私

正式恢复卡新增“撤销本次配置恢复”按钮和稳定 AutomationId。按钮只在当前可写 session 持有有效令牌时可见。对话框默认按钮为取消，并明确说明仅恢复 Long方格配置，不操作真实窗口或桌面文件。UIA 状态只呈现有限枚举与 `DesktopWindowsChanged=False`，不显示操作 ID、指纹、配置内容、显示器身份或路径。

## 5. 自动化证据

定向测试覆盖令牌字段、双指纹、显式确认、revision 陈旧、令牌不一致、当前配置变化、恢复状态变化、一次消费、取消保留、外部编辑失效、保存拒绝保留以及空参数边界。全量测试当前为 405/405；CI 等价覆盖率为行 91.80%（10418/11348）、分支 83.92%（2766/3296），通过仓库 90%/75% 门槛；Debug/Release 构建零警告零错误；UI 源码合同增至 118 个 AutomationId 并通过。

启动链、单实例合同、Issue #19/#20/#23/#24 `ValidateOnly`、配置持久化和漏洞门禁均通过；DesktopHost、文件操作安全与缩略图隔离按已记录限制返回 `Conditional Pass`。真实 UIA 复跑时 PID 39208 仍响应正常但 `MainWindowHandle=0`，`FindFirst` 返回 `0x8000FFFF (E_UNEXPECTED)`，因此判定为环境 `Inconclusive`，不计作产品通过或失败。远端 CI 在发布流程中继续复核。

## 6. 未关闭风险与下一阶段

- 一次性撤销仅覆盖本次配置级布局恢复，不是跨动作历史栈或活动中心；
- App 重启后不恢复撤销令牌，避免额外持久化恢复前敏感快照；
- Issue #20 动态显示、DPI、旋转与登录会话人工矩阵仍 Pending；
- 真实窗口批处理适配器仍未连接，桌面文件与 Explorer 操作为零；
- 干净 Windows 会话的真实 118-ID UIA 仍需补证。

下一阶段应先审计真实窗口提交的准入条件与人工矩阵证据，不应直接连接适配器。只有配置确认/撤销、拓扑陈旧门禁、窗口捕获/应用/验证/回滚和可访问交互均形成可复核闭环后，才允许把 DesktopHost 批处理接入产品 App。
