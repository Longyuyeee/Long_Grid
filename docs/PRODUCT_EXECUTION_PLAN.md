## 2. 统一产品定义

Long方格是 Windows 10/11 桌面盒子管理与任务栏美化软件。产品核心只有三根支柱，必须先把三者做完整，再扩展外围能力：

1. **桌面盒子**：用户在 Windows 桌面空白处右键创建盒子，并直接在桌面移动、缩放、折叠、锁定、重命名、删除和调整外观；
2. **文件夹绑定**：盒子可以绑定一个真实文件夹，在桌面显示和管理该文件夹内容，并清楚处理刷新、离线、权限和失效路径；
3. **任务栏美化**：用户通过可视化预设改变受支持的系统任务栏透明度、颜色和材质，并能可靠恢复系统默认。

Explorer 拖放、盒子间改归属和盒子属性属于上述核心的必要交互。自动整理、Tab、Peek、工作空间、小组件和 Long助手插件均为建立在三根支柱之上的扩展功能，不得再次抢占核心闭环。

产品承诺保持不变：本地优先、轻量常驻、零惊吓、不注入 Explorer、不擅自移动或删除用户文件。首版默认使用安全引用模式。

## 3. 2026-08-25 统一审计结论

### 3.1 已有工程资产

- WinUI 3 应用、单实例、配置存储、恢复、撤销、导入导出和一键启动/打包链已经存在；
- DesktopHost 已具备方格创建、布局、标题操作、图标/缩略图、选择、键盘导航、安全打开和框选等正式工程路径；
- PF-001～PF-006 已达到 `EngineeringComplete / ProductEvidencePending`；
- PF-007A1 已完成 `CF_HDROP` 有界解析、安全准入和一次原子配置请求；
- 文件安全、失败关闭、CAS 持久化、恢复和自动化门禁是当前最可靠的资产，必须保留。

### 3.2 当前不是合格软件体验的原因

代码审计显示，正式控制中心仍沿用早期“开发期只读 UI Shell”的信息架构：

- 一级导航为“概览、首次整理、外观与 Token、安全边界、恢复预览”；
- 首屏反复展示“只读、尚未连接、不会修改、等待会话、证据清单、仍需关闭的门槛”；
- 首次整理仍包含匿名内存练习和拖放语义教学；
- Design Token、开发状态和安全审计被直接当成面向用户的产品模块；
- 真实方格管理能力被大量说明文字、状态卡和原型入口包围；
- `MainWindow.xaml` 约 141 KB，`MainWindow.xaml.cs` 约 231 KB，页面、原型、诊断和业务协调过度集中。

因此用户看到的是“开发教程和验证控制台”，不是桌面管理软件。安全边界本身没有错，错误在于把内部工程语言长期放在产品主路径中。

### 3.3 进展缓慢的根因

1. 以工程切片和 Stage 文档计数，而不是以完整用户旅程计数；
2. 自动化和安全底座持续扩展，但物理可见产品闭环长期为 Pending；
3. 原型页面没有在能力成熟后退出正式导航；
4. `MainWindow`、`App`、DesktopHost Surface 和 Lifecycle 类持续膨胀，修改成本逐步增加；
5. 当前状态被 README、Stage 153、各最新审计和聊天重复维护，出现互相矛盾；
6. 每项功能继续细分 A/B/C 阶段，却没有设置“用户可以完成整个任务”的强制出口。

这属于执行偏移，不是产品愿景偏移。后续应保留安全工程成果，但立即重建产品壳层和交付节奏。

## 4. Long_Decompress 界面参考审计

参考仓库：[Longyuyeee/long_Decompress](https://github.com/Longyuyeee/long_Decompress)。本次实际检查了其 `MainLayout.vue`、路由、Design Token、动效样式和仓库截图。

值得统一到 Long 产品家族的语言：

- 左侧固定品牌区，品牌图标、产品名和一句产品定位清晰可见；
- 一级导航数量有限、名称均为用户任务，不出现技术术语；
- 当前模块使用强调色、图标和左侧指示条，不只依赖颜色；
- 页面顶部使用“大标题 + 一句话说明 + 右侧唯一主操作”；
- 主内容区直接呈现真实任务、文件、进度或设置，不先展示教程；
- 浅色/深色、卡片、边框、圆角、阴影和强调色由统一 Token 控制；
- 180～300 ms 的可中断页面和控件动效，减少动画时可关闭；
- 窄窗口将侧栏压缩成图标栏，而不是产生横向滚动；
- 状态、进度和隐私承诺放在稳定的次级位置，不遮挡主任务。

不应照搬的部分：

- 不复制解压业务的信息密度、任务队列结构或暖黄色配色；
- 不把每个未来功能预先放入导航；未实现模块应隐藏，不显示大量禁用占位页；
- 不照搬 Web/Tauri 技术实现，Long方格继续使用 WinUI 3 和 Windows 原生无障碍能力；
- 不使用持续模糊、强发光或大面积动画增加空闲资源占用。

统一设计方向定义为：**Long 产品家族化、现代扁平、精致华丽、直接可用、低噪声**。Long方格使用更偏冷静的靛蓝/蓝紫强调色和桌面空间感，保持与 Long解压同族但能被清楚区分。

## 5. 产品表面与职责

### 5.1 桌面表面：第一产品主角

桌面方格承担 80% 的高频行为：

- 桌面空白处右键创建盒子，并支持拖动、缩放、折叠、锁定、重命名和删除；
- 将盒子绑定/解绑到一个真实文件夹，显示绑定位置和当前健康状态；
- Explorer 拖入、方格间拖放、选择、框选、排序和打开；
- 当前动作反馈、失败原因和一次撤销；
- 快速隐藏、Peek、搜索和 Portal 等后续高频能力。

用户完成普通整理时不应被迫打开控制中心。

### 5.2 控制中心：管理与配置

控制中心采用稳定侧栏，MVP 导航固定为：

1. **桌面概览**：盒子数量、绑定文件夹、当前状态、最近动作和“新建盒子”；
2. **盒子管理**：真实盒子列表、文件夹绑定、搜索、排序、属性和批量管理；
3. **个性化**：盒子主题、标题、透明度、动效，以及核心任务栏美化预设与恢复；
4. **布局与恢复**：显示器布局、快照、差异预览和恢复；
5. **自动整理**：扩展规则、建议预览、冲突和撤销；未交付前不进入发布构建导航；
6. **设置**：启动、快捷键、行为、隐私、插件、诊断和关于。

小组件在运行时具备真实管理能力后增加独立模块。单文件夹绑定是核心盒子类型；多目录标签、复杂 Portal 导航和高级文件操作属于后续增强，不为单一类型新增顶级导航。

### 5.3 退出主导航的现有内容

| 现有内容 | 新归属 |
|---|---|
| 首次整理匿名练习 | 仅首次启动的 2～3 步引导；完成或跳过后不常驻导航 |
| 外观与 Token | 改为“个性化”，只展示用户能立即应用的真实设置 |
| 安全边界 | 设置 → 隐私与安全；危险动作在发生位置显示上下文确认 |
| 恢复预览匿名场景 | 布局与恢复中的真实快照/差异状态 |
| 证据清单、门槛、开发期状态 | 设置 → 高级诊断；默认折叠，发布版不展示工程术语 |
| 开发期只读 UI Shell 标记 | Debug 构建标题/关于页；不得占用正式标题栏品牌区 |
| Design System 样例卡 | 移出产品 UI，保留到开发预览或测试页面 |

## 6. 页面和视觉基线

### 6.1 桌面概览首屏

打开应用后必须在 3 秒内回答三个问题：我有多少方格、当前是否正常、下一步最常用动作是什么。

推荐结构：

```text
┌ 品牌侧栏 ─────────┬ 桌面概览                         [＋ 新建方格] ┐
│ Long方格          │ 管理桌面上的方格、项目与布局                 │
│ 桌面概览          ├─────────────────────────────────────────────┤
│ 方格管理          │ [6 个方格] [128 个项目] [自动整理：已暂停]  │
│ 自动整理          │                                             │
│ 布局与恢复        │ 我的方格                                    │
│ 个性化            │ [项目 A] [待处理] [常用工具] ...            │
│ 设置              │                                             │
│                   │ 最近动作：3 个项目已加入“项目 A” [撤销]    │
└───────────────────┴─────────────────────────────────────────────┘
```

首屏禁止出现长段开发说明。安全引用只在首次引导、拖放反馈和帮助中用一句人话说明，例如“只加入引用，不会移动原文件”。

### 6.2 设计令牌

- 品牌强调色：以现有 `#5B5FF5` 靛蓝为基准，补齐 hover、pressed、selected 和高对比映射；
- 背景：系统 Mica/纯色基底；卡片使用轻量 Surface，不叠加多层 Acrylic；
- 文字：页面标题 28～32、模块标题 18～20、正文 14、辅助 12；正文不使用全大写工程标签；
- 间距：4/8/12/16/24/32 的 8pt 主网格；
- 圆角：控件 8、卡片 12、主要容器 16；
- 阴影：只表达浮层、拖拽和选中提升，不让每张卡片长期悬浮；
- 图标：统一 Fluent Symbol 或 Long 自有几何图标，不混用 Emoji；
- 动效：hover 120～160 ms，页面/面板 180～240 ms，布局恢复不超过 300 ms；必须可中断并服从减少动画；
- 响应式：宽度小于约 840 effective px 时侧栏压缩为图标模式，内容保持无横向滚动；
- 主题：浅色、深色、跟随系统、高对比均为必测状态。

### 6.3 状态语言

每个主页面只实现与真实数据绑定的：Loading、Empty、Ready、Partial、Error、Recovery。错误说明“发生了什么、是否改变文件、现在能做什么”。开发名词如 revision、generation、CAS、UIA、HDROP 不进入普通用户文案。

## 8. 里程碑与严格出口

### M1：桌面盒子与文件夹绑定核心

目标：用户启动后看到正常控制中心，并能在真实桌面完成“右键创建盒子 → 绑定文件夹 → 调整盒子设置 → 浏览/打开内容 → 拖入项目 → 撤销”。

必须交付：

- UI-R1 产品壳层与信息架构重构；
- UI-R2 桌面概览和方格管理绑定真实工作区；
- BOX-R1 桌面右键菜单创建盒子并进入统一创建事务；
- FOLDER-R1 单文件夹绑定、解绑、刷新、打开和健康状态；
- PF-007A2 DesktopHost 真实 `IDropTarget`；
- PF-007B 方格间拖放与一次撤销；
- PF-001～PF-007 关键物理鼠标、键盘、Narrator、高对比和截图证据；
- 根目录一键启动、Debug/Release 构建继续通过。

出口：一名未读过开发文档的测试者可在 2 分钟内完成上述旅程；主界面不出现开发教程或虚假能力；绑定文件夹不会被静默搬移；所有操作前后真实文件哈希和位置符合预期。

### M2：任务栏美化核心

目标：像 iTop 一样用简单预设完成任务栏美化，同时把 Windows 版本风险、冲突和恢复做得更可靠。

必须交付：TASKBAR-R1 兼容性探测和独立故障域；TASKBAR-R2 系统默认/清透/深色半透明/浅色半透明/Acrylic（仅支持时）预设；TASKBAR-R3 15 秒确认、自动回退、Explorer 重启恢复、冲突检测和“一键恢复系统默认”；TASKBAR-R4 Windows build、多显示器、全屏、高对比和卸载恢复真实矩阵。

出口：用户不理解内部 API 也能选择、预览、保留或撤销预设；不支持的 Windows build 明确拒绝；崩溃、Explorer 重启、禁用和卸载均能恢复系统默认；不注入或 Hook Explorer。

M1 和 M2 同时完成，才可以称为“Long方格核心功能完成”。

### M3：桌面管理增强

目标：在三根核心支柱稳定后增加自动整理和日常效率能力。

必须交付：PF-008～PF-011、PF-020～PF-022、PF-030～PF-033、PF-041～PF-042 高级 Portal、PF-050～PF-052，以及完整搜索、排序、视图和布局档案。

出口：自动建议可解释并可撤销；Portal 权限/离线/重命名/拖放状态可恢复；多显示器真实矩阵通过。

### M4：工作空间与生态

目标：在核心稳定后吸纳 iTop 的产品宽度，但保持隔离和可恢复。

必须交付：PF-060 应用工作空间、PF-070 视觉精修、Widget Host、LPWP 1.x Long助手互操作、插件权限、崩溃隔离、兼容矩阵和一键禁用。

出口：关闭实验后 Windows 外观完全恢复；Widget/插件崩溃不影响 DesktopHost；Long助手与 Long方格运行相同 Golden Fixtures；未实现能力不在正式导航中占位。

### M5：可分发产品

目标：完成 PF-071、PF-090、签名安装、升级/卸载、隐私与支持闭环。

出口：受保护签名、安装/升级/卸载、SBOM、哈希、崩溃恢复、性能和辅助功能门禁全部通过，才允许 Beta/Stable。

## 10. 真实测试与差异修正规则

每个用户可见 PR 必须在描述和本文状态中记录：

| 字段 | 必填内容 |
|---|---|
| 预期效果 | 用户从什么状态执行什么动作，应看到什么结果 |
| 测试环境 | Windows build、DPI、主题、构建、真实输入方式 |
| 实际效果 | 实际窗口、操作、耗时、截图/录像/日志和数据结果 |
| 差异 | 与预期不一致的视觉、交互、性能、无障碍或数据事实 |
| 修正 | 本 PR 修正内容，未修正项的风险和明确后续编号 |
| 文件安全 | 操作前后文件数量、路径、哈希是否变化 |

禁止：仅凭 XAML 存在、AutomationId、静态合同、Mock、内存原型或截图成功声明产品完成。自动化负责防回归，真实键鼠/触控/Narrator/显示环境负责证明产品效果。

## 11. 开发节奏与文档瘦身

- 一个 PR 交付一个可演示的用户结果，建议控制在 1～3 个工作日；
- PR 开始前在本文领取当前编号，完成后只更新该编号和真实差异；
- 普通功能不新增编号 Stage 文档；证据写入 PR、测试结果和本文状态；
- 只有 R3/R4 平台风险、架构决策、协议版本或发布门禁需要专项审计/ADR；
- 不因为物理证据 Pending 无限开发新邻接底座；工程完成后必须安排产品证据冲刺；
- 未实现功能不得提前出现在主导航；
- 每周只报告 M1～M5 用户旅程完成度、当前阻断和下周唯一目标；
- `Complete` 只表示用户旅程、真实证据、自动化和安全门禁同时满足。
